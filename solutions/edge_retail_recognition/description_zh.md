## 它做什么

一台摄像头看着收银台传送带或货架。单类检测器把画面里的每一件商品框出来——
它不做分类，只回答"这里有一件商品"。每个框被裁下来、编码成 512 维向量，
再按余弦相似度在 FAISS 商品库里检索。收银台按 track id 聚合，同一件商品经过相机只计一次；
货架按 planogram 货位聚合，输出 ok、empty、wrong_sku、unknown 四态。
整体一帧一条 MQTT 消息发出去，带着产生它的商品库版本与模型哈希。

这么拆的意义在注册。加一个 SKU 就是拍 3 到 8 张图、发给管理端——检测器不学它，
嵌入器也不学它，全程不重训，商品库多出一个不可变版本（带 SHA256SUMS，可回滚）。
管理端已实现；设备端自动拉取版本的运行时还没做，目前随部署下发。

## 你会得到什么

- **单类 YOLOX-Tiny 检测器**，两个固定 preset：收银台 640²、货架 1280²。
  输入尺寸是编译产物的属性，运行时不改。
- **用 ArcFace 微调的 DINOv2 嵌入器**，两个尺寸：DINOv2-base（348 MB fp32）
  与 DINOv2-small（23.5 MB 动态量化 INT8，供 CPU 路径使用）。
- **版本化商品库**——不可变版本目录，内含向量、SKU 表、FAISS 索引、manifest 与
  SHA256SUMS；原子切换、单写锁、可回滚。每个版本都记下是哪个嵌入模型产生的，
  因为不同模型的向量不可比。
- **注册查询服务与管理界面**，三个容器加一个 MQTT broker。三档角色 token 闸门，
  没有匿名读。
- **各平台的转换路径**：Rockchip NPU（RKNN）与 Hailo-8（HEF），含转换脚本、
  校准配方，以及把转换产物与 CPU 参考对齐的 parity 流程。

## 适用场景

希望收银台读一篮子商品而不是逐件扫码的收银道。希望不用人走一遍就报出缺货与错放的货架。
每周上下架 SKU、等不起每次都跑一轮训练的门店。

不适用于需要法定计量、法律意义上的价格，或者防损检测的场合——它只数它看得见的东西。

## 实测到什么程度

| 收银台能得到什么 | 典型值 | 设备 |
|---|---|---|
| 2956 帧收银回放中的丢帧 | **0** | reComputer J40（Orin NX 16GB） |
| 商品识别，DINOv2-base，每 SKU 注册 8 张 | **top-1 84.67% / top-5 96.66%** | 模型数字，换主机仍然成立 |
| 商品识别，DINOv2-small，每 SKU 8 张 对 1 张 | **top-1 79.11% → 51.11%** | 同上 |

对精度影响最大的是注册张数——同一个模型上，从 1 张加到 8 张，top-1 差 28 个百分点——
所以注册时请为每个 SKU 多拍几个角度。

货架档主机做同一件事更慢：reComputer RK3588 上跑 20 SKU 货架回放，从画面到识别结果
发出是 p50 924 ms / p95 1153 ms，发布错误 0 次。Hailo-8 套餐目前停在模型转换阶段。

## 输出接口

| 接口 | 位置 | 内容 |
|---|---|---|
| MQTT 「retail/v1/events」 | broker，1883 | 一帧一条，带这一帧的所有框：track id、bbox、SKU、相似度、top-2 间距、OCR 块、兜底标志，外加商品库版本与模型哈希 |
| HTTP 「/v1/gallery/*」 | 服务，8089 | 注册、版本列表、单版本 manifest、设备拉取的 tar.gz，以及回滚 |
| HTTP 「/api/*」 | 界面，8080 | 事件列表、单事件逐框详情，以及支撑收银台/货架看板的汇总 |

## 使用须知

- **至少三个视角注册。** 少于三张会被拒绝。正面、背面、侧面加两种光照是可用的下限；
  实测从 1 张加到 8 张，top-1 涨 28 个百分点。
- **按裁剪数量做一帧的预算，不要按帧率。** 以 Hailo-8 路径为例：检测 9 ms，
  嵌入每裁剪 92 ms，五件商品的篮子约半秒；货架一帧按实测密度约 14 秒，
  所以货架场景需要抽帧或按货位采样。
- **两个容器镜像在部署时构建。** 都在管理端主机上从上游仓库构建，且要先构建 SPA。
- **随包的 broker 是匿名明文的。** 进店之前先加账号与 TLS。
- **模型、预处理与商品库版本绑在一起。** 一个嵌入器建的库，另一个读不了；
  版本 manifest 同时记两个哈希，就是为了这件事。
- **模型是在电商棚拍图上微调的。** 对你自己的货架做出任何承诺之前，先用自采图片测一遍。

## 许可说明

项目代码与 DINOv2 骨干是 Apache-2.0，但随包的两个模型权重**都不能商用**：
检测器权重训练在 SKU-110K 上（仅限学术与非商用、禁止衍生作品），嵌入器权重微调自
京东 Products-10K（仅限非商用研究与教育）。商用部署必须用自采或许可宽松的数据
重训两个模型，并重建所有商品库版本。摘要见 「gallery/ATTRIBUTION.md」。
