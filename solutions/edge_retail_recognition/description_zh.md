## 它做什么

摄像头对着收银台传送带或货架，识别画面里每一件商品的 SKU。收银台输出商品清单，同一件商品只计一次；货架输出每个货位的状态：正常、空缺、错放、未知。新增 SKU 拍 3 到 8 张图注册，不需要重训模型。

## 你会得到什么

- **收银台一次读一篮商品**：输出 SKU 和数量，不用逐件扫码。
- **货架自动报缺货与错放**：不需要人工巡店。
- **新商品拍照注册**：每个 SKU 拍 3–8 张，不重训；商品库有版本，可回滚。
- **管理界面**：注册商品、查看识别事件，以及收银台/货架看板。
- **识别结果实时推送到 MQTT**，可接入自己的系统。

## 适用场景

- 希望一次读完一篮商品、不逐件扫码的收银道
- 希望自动报出缺货与错放的货架
- 每周上下架 SKU 的门店

不适用于法定计量、法律意义上的价格或防损检测。

## 实测效果

| 指标 | 效果 |
|---|---|
| 收银回放丢帧（reComputer J40） | **2956 帧 0 丢帧** |
| 商品识别准确率（DINOv2-base，每 SKU 注册 8 张） | **top-1 84.67% / top-5 96.66%** |
| 注册张数的影响（DINOv2-small） | 8 张 **top-1 79.11%**，1 张 **top-1 51.11%** |
| 货架从画面到识别结果（reComputer RK3588，20 SKU） | **p50 924 ms / p95 1153 ms** |

丢帧与延迟为录制视频回放测得。

## 输出接口

| 接口 | 内容 |
|---|---|
| MQTT 「retail/v1/events」 | 每帧一条：每件商品的位置、SKU 和相似度 |
| HTTP 「/v1/gallery/*」 | 商品注册、商品库版本与回滚 |
| HTTP 「/api/*」 | 事件列表、事件详情与收银台/货架看板数据 |

## 使用须知

- **每个 SKU 至少注册 3 张**，少于 3 张会被拒绝；建议正面、背面、侧面加两种光照。
- **按一帧里的商品数估算延迟**：Hailo-8 路径货架一帧约 14 秒，货架场景需抽帧或按货位采样。
- 新的商品库版本目前随部署下发，设备还不能自动拉取。
- 两个容器镜像在部署时于管理端主机上构建。
- 随包的 MQTT broker 是匿名明文的，进店前需加账号与 TLS。
- 更换嵌入模型后需重建商品库，旧商品库不能继续使用。
- 模型在电商棚拍图上微调，上线前先用自家货架图片测一遍。

## 许可说明

项目代码与 DINOv2 骨干为 Apache-2.0，但**随包的两个模型权重都不能商用**：检测器权重训练自 SKU-110K（仅限学术与非商用），嵌入器权重微调自京东 Products-10K（仅限非商用研究与教育）。商用部署需用自采或许可宽松的数据重训两个模型，并重建所有商品库版本。详见 「gallery/ATTRIBUTION.md」。
