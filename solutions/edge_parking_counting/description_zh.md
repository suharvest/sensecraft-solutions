## 这个方案能帮你做什么

停车场想知道「现在场内还有几个空位」，通常要在每个车道埋地感线圈或装道闸计数器。这个方案用出入口现有的网络摄像头：在画面里设一条计数线，车辆越线时记一次进或出，场内车辆数和剩余车位实时发到你的系统。

## 核心价值

| 好处 | 具体说明 |
|------|---------|
| 用现有摄像头 | 接入出入口已有的 RTSP 网络摄像头，不用埋线圈、不改道闸 |
| 进出分开计数 | 每辆车越线时判断是驶入还是驶出，同一车道双向通行也能分开统计 |
| 剩余车位实时更新 | 每次进出后立即发布场内车辆数和剩余车位，可直接驱动余位显示屏或停车系统 |
| 本地处理 | 画面在出入口旁的设备上分析，视频不上传云端，只发出计数结果 |
| 区分车型 | 识别轿车、摩托车、公交车和卡车，每条进出记录都带车型 |

## 适用场景

| 场景 | 怎么用 |
|------|--------|
| 商场、写字楼停车场 | 入口余位屏显示「剩余 37 个车位」，数值随车辆进出自动变化 |
| 园区、工厂大门 | 统计每天进出车辆数，按车型区分货车和小车 |
| 停车场满位提醒 | 剩余车位降到 0 时，停车系统收到消息后切换「车位已满」提示 |
| 多个出入口汇总 | 每个出入口各部署一套，上层系统按停车场编号汇总全场车辆数 |

## 部署效果

部署完成后，设备每检测到一辆车越过计数线，就向你的 MQTT 服务器发两条消息：

- **进出记录**（主题 `<停车场编号>/parking/<出入口编号>/crossing`）：方向（驶入 / 驶出）、车型、识别置信度、越线后的场内车辆数和剩余车位。
- **场内概况**（主题 `<停车场编号>/parking/<出入口编号>/occupancy`）：场内车辆数、车位总数、剩余车位、今日驶入数、今日驶出数。

你的停车管理系统、余位显示屏或 Home Assistant 订阅这两个主题即可使用这些数据。

## 使用须知

### 核心硬件设备

| 设备 | 说明 | 必需 |
|------|------|------|
| reComputer J30 系列（Jetson Orin Nano） | 分析摄像头画面并计数；需 JetPack 6.2 | 二选一 |
| reComputer RK3588 系列 | 分析摄像头画面并计数 | 二选一 |
| 出入口网络摄像头 | 支持 RTSP 视频流（H.264 或 H.265），固定拍摄车道 | ✓ 必选 |
| MQTT 服务器 | 接收计数结果，可用现场已有的服务器或自行安装 Mosquitto | ✓ 必选 |

### 网络要求

- 计数设备、摄像头和 MQTT 服务器需在同一局域网内，或彼此网络可达
- 首次部署需要联网下载应用（约 0.5–0.7 GB）和识别模型；之后可断网运行
- 一套设备接一路摄像头，对应一个出入口

## 方案对比

| | reComputer J30 系列（Jetson Orin Nano） | reComputer RK3588 系列 |
|---|---|---|
| 设备实测处理速度 | 每秒 30 帧（输入 640×360、30 帧/秒） | 每秒约 3 帧（输入 1280×720、5 帧/秒） |
| 单帧分析耗时 | 约 3.6 ms | 约 18 ms |
| 适合的出入口 | 车辆正常行驶通过的出入口 | 车辆减速或停车抬杆后通过的道闸出入口 |
| 系统要求 | 仅支持 Jetson Orin Nano 模组，JetPack 6.2 | 部署时自动检查板上的 NPU 运行库和视频解码库，缺少时提示安装 |

Jetson Orin Nano 实测：30 帧/秒测试视频中，41 次越线全部计入，进出方向全部正确。RK3588 每秒处理约 3 帧，车辆经过计数线时需在画面中停留约 1 秒以上才能被稳定计数。
