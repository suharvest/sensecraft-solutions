## 这个方案做什么

摄像头盯住一块室内区域，在设备本地判断有没有人跌倒，并把事件推送到 Home Assistant、护理呼叫系统、NVR 或你自己的服务。视频不出设备，网络上只传一条 JSON 消息。

## 你会得到什么

- **跌倒事件推送**：每个人单独跟踪，一次跌倒只触发一次事件。
- **Home Assistant 实体自动出现**：跌倒传感器、状态、事件编号、有人存在，无需手写 YAML。
- **可接现有摄像头**：reComputer 套餐接入标准 RTSP 摄像头。
- **可选告警面板**：识别区域、无人/静止超时、值班人确认、webhook 通知。
- **实时预览**：部署完成后查看骨架与每个人的状态，用于调整机位。

## 适合接到哪里

- **养老与居家照护**：无人看管的卫生间、走廊、卧室。
- **已有的摄像头**：不换摄像头即可加上跌倒检测。
- **Home Assistant 自动化**：跌倒时开灯、推送通知或发起呼叫。

## 实测效果

| 指标 | 效果 |
|---|---|
| 跌倒到告警 | 平均 **1.61 秒** |
| 跌倒召回 | **100%** |
| 日常动作不误报 | **80%** |
| 单台主机 15 FPS 同时接入 | **16 路** |
| 经告警面板到 webhook 送达 | **P50 2.83 秒**（确认窗口调短为 1 秒） |
| 各平台准确率 / 平均告警时延 | **74.1%–88.9%** / **1.22–1.75 秒** |
| 独立外部数据集（RealBiomFall）召回 | **52.9%–58.8%** |

测试设备为 reComputer R2000（Hailo-8），数据集为 GMDCSA-24 留出集 27 段（12 段跌倒 / 15 段日常动作），15 FPS 室内中近距离画面。

## 输出接口

| 输出 | 内容 |
|---|---|
| MQTT 「<设备名>/fall-detection/results」 | 每帧一条 JSON：整体状态与每个被跟踪者的状态 |
| MQTT 「<设备名>/fall-detection/status」 | 设备在线 / 离线 |
| MQTT 「homeassistant/」 自动发现 | 跌倒传感器、状态、事件编号、人数 |
| RTSP 8554 「/live0」（reCamera）或你的 IP 摄像头 | 检测画面 |
| HTTP 8080 「/api/alarms」（仅告警面板） | 告警列表，确认、驳回、标记已处置 |
| webhook POST（仅告警面板） | 告警 id、类型、区域、时间与操作者，不含视频 |

「<设备名>」 在部署步骤中填写。

## 方案对比

| 套餐 | 摄像头 | 15 FPS 实测路数 | 告警面板 |
|---|---|---|---|
| reCamera 2002 | 一体化 | — | 需另加一台主机（reComputer R1000 或已有机器） |
| reCamera Pro | 一体化 | 1 路 | 需另加一台主机（reComputer R1000 或已有机器） |
| IP 摄像头 + reComputer J30 / J40 | 现有 RTSP 摄像头 | J30 8 路 / J40 9 路 | 同机运行，8080 端口 |
| reComputer RK3576 / RK3588 | 现有 RTSP 摄像头 | RK3576 1 路 / RK3588 5 路 | 同机运行，8080 端口 |
| reComputer R2000（Hailo-8） | 现有 RTSP 摄像头 | 16 路 | 同机运行，8080 端口 |

**单个房间、最快跑通**选 reCamera 2002；**已有摄像头或需要多个视角**选 reComputer 套餐。

## 告警面板

- **站点总览**：房间、摄像头、区域数量与 24 小时告警趋势；摄像头断流时显示「未知 + 断流」。
- **在实时画面上画识别区域**，不用手填坐标。
- **每个区域三类告警**：跌倒、区域无人超时、人静止超时，超时时间按区域单独设置。
- **值班人确认**：5 秒取证后等待 60 秒确认或驳回，无人应答默认按真实告警通知。
- **断网后补发且不重复**：断网恢复实测排队的 3 条全部送达、无重复。
- **全本地运行**：通知不含视频和快照，记录保留 90 天。

### 语音确认（可选）

默认关闭。开启后告警时向房间播报「您还好吗？请回答」：呼救、无回答或听不懂立即确认告警；「我没事」默认只标记待复核，不关闭告警。需在面板主机上接 USB 麦克风与扬声器，并提供一个 OpenVoiceStream 实例。音频不落盘。

## 使用须知

- **本方案不是医疗器械，也不是经认证的紧急救援产品**，告警需由人判断和响应。
- **机位决定准确率**：2–3 m 侧向或斜角、肩部和髋部可见；垂直俯拍、远景和遮挡会变差。

  ![机位示意：2–3 m 的侧向或斜角机位可用；垂直俯拍、远景和被遮挡的机位不可用。](https://files.seeedstudio.com/Solution/landpage_asset/fall-detection/camera-placement-be3fb598.svg)
- 跌倒过程必须发生在画面里，启动时人已躺着不会产生事件。
- 部署预设为单路摄像头；上表路数为另行测得的最高负载，定路数前用自己的摄像头测一遍。
- MQTT broker：reCamera 2002 自带；reComputer 套餐随检测器启动；reCamera Pro 不带，需指向外部 broker 或在设备页面查看结果。
- 移动或重新对准摄像头后需重新核对识别区域，系统不会报错。
- 睡眠时段会触发静止超时，区域需排除床位或把超时调长；遮挡可能触发一次「无人」误报。
- RK 板卡上无人告警从不触发时，先确认画面无人时检测器仍在发消息。
- 面板中的 Telegram 与邮件通道不可用。
- reCamera 同一时间只能跑一个视觉应用，安装会接管 Node-RED 与其他视觉应用。
