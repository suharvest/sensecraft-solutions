## 套餐: reCamera {#recamera}

一台摄像头把事情做完。摄像头上的控制台带有应用画廊——安装目标检测、文字识别、
人脸分析、跌倒检测或客流统计，在浏览器里随时切换，并把当前应用产生的结果
通过 MQTT 发到 Home Assistant。

| 设备 | 作用 |
|------|------|
| reCamera | 运行控制台、AI 应用、RTSP、ONVIF 和本地 MQTT broker |
| 电脑或 reComputer R1100 | 可选——第 3 到 5 步用它运行 Home Assistant 和 MQTT broker |

**同一时间只有一个应用占用摄像头。** 切换应用会停掉前一个及其 RTSP 和 MQTT 输出；
不会卸载任何东西，切回来只需要点一下。

## 步骤 1: 升级 reCamera 控制台 {#deploy_console type=recamera_cpp required=true config=devices/recamera_console.yaml}

安装 0.5.5 版控制台，摄像头的应用由它管理。已经是这个版本就会自动跳过。

### 前置条件

1. 用 USB 连接摄像头，或让它和这台电脑处于同一网络。
2. USB 连接时地址是 `192.168.42.1`；走 Wi-Fi 就用路由器上显示的 IP。
3. 用户名 `recamera`，默认密码 `recamera`（较早的机器是 `recamera.2`）。
4. 新设备需要先打开 SSH——用 USB 连接，等约两分钟启动完成，打开 `http://192.168.42.1/#/security` 登录后把 SSH 开关打开。
5. 控制台已经是 0.5.5 就不会重装：动任何东西之前会先查版本，然后把这一步标记为已跳过。
6. 摄像头的操作系统是另外升级的，在本应用的**设备管理 → 嵌入式 → reCamera** 里。本方案不要求做这一步；如果摄像头版本很旧可以做一次，注意它会刷写整个系统，需要几分钟。

### 故障排查

| 问题 | 解决方法 |
|------|----------|
| 连不上 | USB 用 `192.168.42.1`；走网络就到路由器里查 IP |
| 密码不对 | 默认是 `recamera`，较早固件的机器是 `recamera.2` |
| 安装失败 | 重启摄像头后重新执行这一步 |
| Node-RED 用不了了 | 属于正常——控制台接管了摄像头流水线。可以在控制台的系统设置里切回去，什么都没被卸载 |
| 想恢复原来的面板 | 按住 **User** 键再插电，等红灯停止闪烁并常亮后松开——这会把摄像头恢复出厂设置 |

---

## 步骤 2: 挑选并安装应用 {#open_console type=web_dashboard required=true config=devices/console_dashboard.yaml}

打开控制台，从画廊里装一个应用，启用它，然后查看结果。

### 前置条件

1. 用摄像头自己的账号密码登录，和上一步是同一套。
2. 打开**应用**页。已装的应用会列出来，**从云端安装**里是还可以装的应用。
3. 下载是浏览器做的，再把数据推给摄像头，所以摄像头不需要联网——但这台电脑需要。
4. 选一个应用点**安装**。模型随应用一起装，所以一个应用可能有几百 MB，控制台会先告诉你大小。
5. 启用这个应用。切换会把摄像头交给它，并停掉之前运行的那个。
6. 在运行中的应用上点**调试**，就能看到实时画面和检测结果。

### 部署完成

摄像头正在运行你选的应用，到这里它已经可以单独使用了。

控制台在 `http://<摄像头 IP>/`：应用画廊用来装应用和切换应用，实时画面用来确认
摄像头看到了什么，网络、隐私和系统设置在其他页面里。

这些应用同时响应 ONVIF，所以 NVR 或视频管理平台可以自动发现这台摄像头并拉流，
不需要你手填 RTSP 地址。

第 3 到 5 步是可选的。想把结果放进 Home Assistant 而不只是留在摄像头页面上，就继续做。

### 故障排查

| 问题 | 解决方法 |
|------|----------|
| 页面打不开 | 等一分钟让摄像头重启完成，再刷新 |
| 登录被拒 | 用摄像头自己的账号密码，默认 `recamera` / `recamera` |
| 连不上应用目录 | 是这台电脑访问不了 `sensecraft-statics.seeed.cc`。可改用**上传 .deb**，或者先解决这台电脑的网络——问题不在摄像头 |
| 存储空间不足 | 先卸载用不到的应用；控制台会告诉你需要多少、还剩多少 |
| 实时画面是黑的 | 还没有应用在跑，先到画廊里启用一个 |
| 应用在列表里但启动不了 | 它的文件缺失了。卸载后重新安装 |
| 开启隐私打码后摄像头起不来 | 这个设置会替换视频内核模块，需要完整断电重启——请拔掉电源再插上，软件重启不行 |

## 步骤 3: 部署 Home Assistant {#deploy_ha type=docker_deploy required=false config=devices/homeassistant_deploy.yaml}

启动 Home Assistant 和一个 MQTT broker。两者你都已经在跑就跳过这一步。

### 部署目标 {#ha_local type=local config=devices/homeassistant_deploy.yaml default=true}

### 前置条件

1. 已安装并启动 Docker Desktop。
2. 至少 2 GB 可用磁盘。
3. 8123 和 1883 端口空闲。

### 部署完成

1. 打开 **http://localhost:8123**，按向导创建管理员账号。
2. 这台机器的 1883 端口上现在有一个 MQTT broker，第 4 步要填它的地址。
3. broker 放在 Home Assistant 旁边而不是摄像头上是有意的：它得比任何一台摄像头、任何一次应用切换活得更久。

### 故障排查

| 问题 | 解决方法 |
|------|----------|
| 8123 或 1883 端口被占用 | 已经有东西在用了——可能是现有的 Home Assistant 或 Mosquitto。停掉它，或者跳过这一步直接用现成的 |
| Docker 起不来 | 打开 Docker Desktop 应用 |
| 容器反复重启 | 确认至少有 2 GB 可用内存 |

### 部署目标 {#ha_remote type=remote config=devices/homeassistant_deploy.yaml}

### 前置条件

1. 目标设备在网络上且 SSH 可达。
2. 设备上已安装并启动 Docker。
3. 在下面填入它的 IP 地址、用户名和密码。

### 部署完成

1. 打开 **http://\<设备 IP\>:8123**，按向导创建管理员账号。
2. MQTT broker 在同一台设备的 1883 端口上，第 4 步要填它的地址。

### 故障排查

| 问题 | 解决方法 |
|------|----------|
| 连接超时 | 检查网络，先用 ping 测一下 |
| SSH 认证失败 | 核对用户名和密码 |
| 目标机 1883 被占用 | 那里已经有 broker 了——保留它，第 4 步直接填它 |

## 步骤 4: 把摄像头接入 Home Assistant {#connect_ha type=manual required=false config=devices/connect_ha_recamera.yaml}

让 Home Assistant 和摄像头连同一个 broker，实体会自己出现。

### 前置条件

1. Home Assistant 已经在跑，并且你能登录。
2. 有一个可达的 MQTT broker——第 3 步部署的那个，或者你自己的。
3. 摄像头上有应用在运行，也就是第 2 步做完了。

### 部署完成

摄像头的检测结果现在已经在 Home Assistant 里了。

实体来自 MQTT 自动发现，不需要手动添加；在摄像头上换一个应用，实体集合也会
自动跟着变。自动发现带的是结果，不含视频：想在仪表盘上看画面，用自带的
**Generic Camera** 集成添加摄像头的 RTSP 地址——控制台的「集成」页面上就有完整
地址和复制按钮。

### 故障排查

| 问题 | 解决方法 |
|------|----------|
| 摄像头上「测试连接」失败 | broker 地址必须是**摄像头**能访问到的，而不只是这台电脑能访问。确认填的是 broker 所在机器的地址，不是 `localhost` |
| 保存了，但 Home Assistant 里什么都没有 | 确认 Home Assistant 的 MQTT 集成连的是同一个 broker 和端口，然后在控制台里重启一下当前应用 |
| 实体出现了但一直不可用 | 摄像头上没有应用在跑，或者应用被停了。到画廊里启用一个 |
| 换应用之后实体消失了 | 属于正常——每个应用发布自己的一套实体，上一个应用停掉时它的实体会被移除 |

---

## 步骤 5: 在 Home Assistant 里查看结果 {#ha_dashboard type=web_dashboard required=false config=devices/ha_dashboard.yaml}

把画面和检测结果放到同一张卡片上。

### 前置条件

1. **先看看自动发现已经建了什么。** 「设置 → 设备与服务 → MQTT」，点进这台摄像头的设备，它的实体都列在那里，记下你想放到仪表盘上的那几个。
2. **视频要单独加。** 自动发现带的是结果，不含视频。「设置 → 设备与服务 → 添加集成」，选 **Generic Camera**，填入摄像头的视频流地址：
   - Stream Source URL：`rtsp://<摄像头 IP>:8554/live0`
   - RTSP transport protocol：选 **TCP**
   - Verify SSL certificate 不要勾
   控制台的「集成」页面上就有这条完整地址和复制按钮，旁边还有 go2rtc 的配置片段，想转流降低延迟可以用。
3. **搭卡片。** 「设置 → 仪表盘」→ 打开你的仪表盘 → 点铅笔进入编辑 → **添加卡片** → **Picture glance**（图片一览）。把 Camera Entity 设成刚加的 Generic Camera，再把检测实体加进 Entities 列表。它们会以图标形式叠在实时画面上，鼠标悬停能看到状态。
4. **也可以分开放。** **Entities**（实体）卡片把数值按行列出来，对于计数和时间戳比叠在视频上的图标更好读。对同一批实体加一张 **History**（历史）卡片，就能看到一天里的变化。
5. **让它触发动作。** 「设置 → 自动化与场景 → 创建自动化」，触发器选**实体 → 状态**，指向某个检测实体。把数值放进 Home Assistant 而不是留在摄像头上，图的就是这个。

### 部署完成

摄像头现在和 Home Assistant 里其他设备一样了：有画面、有一组状态、背后有历史记录。

在摄像头上换成别的应用，它会发布自己那套实体，所以 MQTT 设备的构成会变，而
Generic Camera 不受影响——视频接的是 RTSP 流，跟跑哪个应用无关。

### 故障排查

| 问题 | 解决方法 |
|------|----------|
| Generic Camera 提示连不上 | 先用 VLC 试这条地址。如果 VLC 能放而 Home Assistant 不行，把 RTSP transport 强制设成 TCP——差别通常就在 UDP 上 |
| 画面是黑的，或者放几秒就卡住 | 已经有别的东西占着这路流。摄像头能带的 RTSP 客户端数量有限，先关掉控制台的实时画面和所有 VLC 窗口 |
| 卡片上有画面，但没有检测图标 | 那些实体来自 MQTT，不是摄像头集成带的。先到「设置 → 设备与服务 → MQTT」里确认它们存在，再加到卡片上 |
| 实体显示 `unknown` | 应用是变化时才发布，所以在摄像头面前没发生什么之前，新实体一直是 unknown |
| Picture glance 不接受某个实体 | 它只接受有状态的实体，不接受设备。加具体的实体，别加设备那一行 |

## 套餐: reCamera Pro {#recamera_pro}

新一代摄像头上的同一套流程。应用放在它的应用中心里，每个应用各自带一份输出配置，
结果进 Home Assistant 的方式和上面一样。

| 设备 | 作用 |
|------|------|
| reCamera Pro | 运行应用中心、AI 应用、RTSP，以及每个应用各自的 MQTT 配置 |
| 电脑或 reComputer R1100 | 可选——第 3 到 5 步用它运行 Home Assistant 和 MQTT broker |

**两个要注意的差别。** 这台摄像头不自带 MQTT broker，在第 4 步给它填上 broker
地址之前，结果只留在设备上；而且这个地址是**按应用**配的，不是整台摄像头配一次。

## 步骤 1: 检查并更新固件 {#firmware_pro type=manual required=false config=devices/recamera_pro_firmware.yaml}

只需要做一次，而且只有当你的摄像头还没有应用中心时才需要。

![设备管理、嵌入式标签页，以及填写地址和 ADB 端口的 reCamera Pro 条目](https://files.seeedstudio.com/Solution/landpage_asset/fall-detection/recamera-pro-firmware-update-a9539b3d.gif)

### 前置条件

1. 先打开摄像头的页面——如果**应用中心**已经在那儿，跳过这一步。
2. 在本应用里：**设备管理 → 嵌入式 → reCamera Pro**，填入摄像头地址，然后点**检查更新设备**。
3. 它走的是 **ADB 5555 端口**而不是 SSH，所以摄像头必须在网络上，只插 USB 不够。
4. 更新过程中摄像头会重启，需要几分钟，中途不要断电。
5. 它会保留一份出厂文件备份，同一页的**恢复出厂设置**可以回滚。

### 故障排查

| 问题 | 解决方法 |
|------|----------|
| 测试连接失败 | 检查地址，以及这台电脑能否访问到 5555 端口 |
| 点了检查更新设备没反应 | 摄像头可能已经是最新的——到它的页面上找一下应用中心 |
| 之后应用中心还是没出现 | 刷新页面；摄像头重启后需要一点时间 |

## 步骤 2: 挑选并安装应用 {#open_appcenter_pro type=web_dashboard required=true config=devices/recamera_pro_apps.yaml}

打开应用中心，装一个应用，启动它，然后看它检测到了什么。

### 前置条件

1. 用摄像头控制面板的账号密码登录——不是 SSH 的那套。
2. 在左侧打开**应用中心**。已装的应用列在这里，点 **+** 会弹出安装对话框，里面读的是在线目录。
3. 每个安装包由浏览器下载、校验 SHA-256 后再上传给摄像头，所以摄像头自己从不联网——联网的是这台电脑。设备上已有的模型会跳过，对话框会告诉你还需要传几个。
4. 有些应用还需要运行时组件。对话框会先问你是否一并下载；选择取消会连应用一起不装，而不是留下一个装了一半的应用。
5. 在应用卡片上点**启动**。同一时间只跑一个推理应用，启动一个会停掉另一个。
6. 应用中心自己没有预览。到左侧的**实时预览**或**实时画面**页去看画面和检测结果。

### 部署完成

摄像头正在运行你选的应用。

结果可以在摄像头自己的页面上看到，但在做完第 4 步之前不会往外走——和 reCamera 不同，
这台机器没有自带 broker。

第 3 到 5 步是可选的。想把结果放进 Home Assistant 就继续做。

### 故障排查

| 问题 | 解决方法 |
|------|----------|
| 页面打不开 | 地址按 `http://` 输入，让浏览器跟着跳转。固件有一个 HTTPS 开关：开着时 80 端口跳到 443，关着时 `https://` 地址会跳回 80 |
| 证书告警 | HTTPS 开关开着时属于正常——摄像头用的是自签证书，继续访问即可 |
| 应用中心是空的，或提示要登录 | 管理接口由控制面板自己的登录 cookie 把关。先登录控制面板，再重新打开这个标签页 |
| 加载目录失败 | 是这台电脑访问不了 `sensecraft-statics.seeed.cc`。如果你自建了目录，安装对话框里的目录地址可以改 |
| 校验和不匹配，拒绝安装 | 下载损坏，或者安装包被重新发布过。重新加载目录再试一次 |
| 应用在列表里但启动不了 | 它的模型缺失了。重新安装一次——安装时会连模型一起下载 |
| 实时预览里没有检测结果 | 可能还有别的推理应用占着摄像头；确认你装的这个是正在运行的那个 |

## 步骤 4: 把摄像头接入 Home Assistant {#connect_ha_pro type=manual required=false config=devices/connect_ha_recamera_pro.yaml}

让 Home Assistant 和摄像头连同一个 broker，实体会自己出现。

### 前置条件

1. Home Assistant 已经在跑，并且你能登录。
2. 有一个可达的 MQTT broker——第 3 步部署的那个，或者你自己的。
3. 摄像头上有应用在运行，也就是第 2 步做完了。

### 部署完成

摄像头的检测结果现在已经在 Home Assistant 里了。

**这份配置属于你刚才配的那个应用，不属于整台摄像头。** 以后再装别的应用，它的
MQTT 输出默认是关的——打开它的「配置」把这一步再做一遍。反过来说，在两个都配好的
应用之间切换，实体集合会自动替换，不用再动配置。

### 故障排查

| 问题 | 解决方法 |
|------|----------|
| 「配置」里没有「结果输出」分组 | 这个应用没有声明输出能力，也就没有 MQTT 可配。它的结果只留在设备上 |
| broker 上收不到任何数据 | 确认 broker 地址是**摄像头**能访问到的，不只是这台电脑能访问。这台摄像头不自带 broker，地址留空数据就出不了设备 |
| 保存被拒绝 | 勾了 MQTT 通道但 Broker 地址为空，或者「主题(base)」为空、含 `+` `#` 或空格，表单都会拦下来 |
| 保存了，但 Home Assistant 里什么都没有 | 确认「输出模式」是 **Home Assistant** 而不是「自定义」或「原始 JSON」，并且 Home Assistant 的 MQTT 集成连的是同一个 broker 和端口 |
| 实体出现了但一直不可用 | 摄像头上没有应用在跑。到应用中心启动一个 |
| 启动别的应用之后实体消失了 | 属于正常——每个应用声明自己的一套实体，没配过的应用一个实体都不发 |

## 步骤 5: 在 Home Assistant 里查看结果 {#ha_dashboard_pro type=web_dashboard required=false config=devices/ha_dashboard_pro.yaml}

把画面和检测结果放到同一张卡片上。

### 前置条件

1. **先看看自动发现已经建了什么。** 「设置 → 设备与服务 → MQTT」，点进这台摄像头的设备，它的实体都列在那里，记下你想放到仪表盘上的那几个。
2. **打开 RTSP，并从摄像头上把地址抄下来。** 在摄像头上：**画面设置 → 推流设置**，协议选 RTSP 并开启。视频流地址会显示在那里，带复制按钮——这条地址是固件给的，直接复制，别自己猜路径。想给流加认证，同一页可以设用户名和密码。
3. **视频要单独加。** 自动发现带的是结果，不含视频。在 Home Assistant 里：「设置 → 设备与服务 → 添加集成」，选 **Generic Camera**，粘贴刚才那条地址，RTSP transport protocol 选 **TCP**。如果开了认证，把凭据写进地址里：`rtsp://用户名:密码@…`。
4. **搭卡片。** 「设置 → 仪表盘」→ 打开你的仪表盘 → 点铅笔进入编辑 → **添加卡片** → **Picture glance**（图片一览）。把 Camera Entity 设成刚加的 Generic Camera，再把检测实体加进 Entities 列表。
5. **也可以分开放。** **Entities**（实体）卡片把数值按行列出来；对同一批实体加一张 **History**（历史）卡片，就能看到一天里的变化。
6. **让它触发动作。** 「设置 → 自动化与场景 → 创建自动化」，触发器选**实体 → 状态**，指向某个检测实体。

### 部署完成

摄像头现在和 Home Assistant 里其他设备一样了：有画面、有一组状态、背后有历史记录。

视频和检测结果走的是两条路，换应用时表现也不一样：Generic Camera 照常工作，
因为它读的是固件的视频流；而 MQTT 实体会被新启动的应用发布的那套替换掉——
没配过 MQTT 的应用一个实体都不发。

### 故障排查

| 问题 | 解决方法 |
|------|----------|
| 推流设置里没有视频流地址 | RTSP 还没开启，或者选的是别的协议。三种协议互斥，选了 RTSP 就会关掉 RTMP 和 ONVIF |
| Generic Camera 提示连不上 | 先用 VLC 试这条地址。如果 VLC 能放而 Home Assistant 不行，把 RTSP transport 强制设成 TCP。如果在摄像头上设了凭据，凭据要写进地址里 |
| 画面是黑的，或者放几秒就卡住 | 已经有别的东西占着这路流，先关掉摄像头自己的实时预览和所有 VLC 窗口 |
| 卡片上有画面，但没有检测图标 | 那些实体来自 MQTT。确认当前运行的应用配过 MQTT（第 4 步），并且实体在「设置 → 设备与服务 → MQTT」里确实存在 |
| 实体显示 `unknown` | 应用是变化时才发布，所以在摄像头面前没发生什么之前，新实体一直是 unknown |
