# 本地 Home Assistant 灯光面板

**接入候选，当前禁用。** 本方案为 reTerminal E1003 的现有固定显示与触摸布局准备
USB 部署内容。目标流程是使用同一份预编译固件，在 App 输入 Wi-Fi、粘贴一个
`light.xxx` 实体，再到 Home Assistant（HA）确认设备和动作权限。
用户无需编辑 `secrets.yaml`、安装 ESPHome、编译或运行维护者脚本。
实现这条用户流程仍需 App 接入。

## 当前提供什么

| 项目 | 当前状态 |
| --- | --- |
| 同硬件、同布局使用一份固件 | 已构建，不含个人 Wi-Fi 或静态 API key |
| USB 配网、独立 API key、目标配置 | 固件维护者客户端已在一台面板验证；App 适配待实现 |
| 重启和 USB 更新后保留配置 | 固件项目已验证两次复位及同图像、同分区 USB 覆盖更新 |
| 灯光控制与屏幕状态一致 | 真实 HA 灯光和触摸待验收；任意目标状态、亮度同步需 Blueprint 或适配 |

## 适用场景

已有 HA 和一盏可调光的灯，例如办公室或床头灯。配置电脑、E1003 和 HA 必须在
同一可达局域网。设备通过加密的 ESPHome 原生 API（TCP 6053）连接 HA，
无需 MQTT，也没有设备网页服务。App 的目标职责是配置，完成后不应依赖 App 常驻。

## 预期效果与使用须知

补齐接入后，面板应控制选定灯光并显示其状态和亮度。
**当前运行时目标写入只设置控制绑定；任意目标的自动显示同步尚未完成。**
HA 发现、真实灯光控制、显示与触摸效果、两台设备隔离及 App 部署仍需验收。

此原型仅支持 USB。当前 OTA 配置规则不支持继承运行时 API key，所以固件已关闭
OTA，不能用无鉴权 OTA 绕过。运行时文本更改后至少等待 65 秒，再断电并检查配置
是否保留。当前无公开固件下载；维护者可按[资源说明](assets/firmware/README.md)
准备校验过的本地审阅包。
