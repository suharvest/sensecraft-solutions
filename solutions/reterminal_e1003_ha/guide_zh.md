## 套餐: 部署 E1003 {#usb_candidate}

一张表单、一次提交：**填写配置 → 自动检查并按需安装 → 保存与复位读回**。目标参考固件为 0.2.1 plaintext-only，无加密选择或密钥复制。
以下是待验收的 0.2.1 / contract 14 目标流程；新构建和最终证据尚未提供。正式候选仍禁用，等待公开契约和固件下载资源；当前人工审阅步骤不执行设备写入。

## 步骤 1: 连接设备并填写配置 {#flash_panel type=manual required=true config=devices/review_flash.yaml}

只有“部署 E1003”一个入口，由 App 判断是否需要安装固件。

### 前置条件

准备兼容测试 App、USB 数据线与灯的 HA 实体 ID。电脑、面板和 HA 需在同一可达局域网；首次联网准备 Wi-Fi 名称和密码。

### 接线

1. 连接 E1003 底板 USB-UART 口与电脑，关闭占用该端口的工具。
2. 在 App 内置表单填写以下配置，后续部署仍在同一表单进行。

| 设置 | 怎么填 |
| --- | --- |
| USB 端口 | 选择已连接的 E1003 |
| 按钮控制的灯 | 粘贴 `light.bedroom` 这类实体 ID；五个灯光触摸区共用此灯 |
| Wi-Fi 名称 | 已有可用网络时留空，无需已有本机 key 记录；首次联网时填写 |
| Wi-Fi 密码 | 填写所选网络的密码；输入默认遮蔽，沿用网络时留空 |

### 故障排查

| 问题 | 处理 |
| --- | --- |
| 找不到端口 | 检查数据线，并关闭占用端口的工具 |
| 仍看到加密项或复制 key | 这是旧版界面；最终 contract 14 入口不提供这些控件，兼容 App 尚待验收 |

## 步骤 2: 部署并保存配置 {#configure_panel type=manual required=true config=devices/review_setup.yaml}

点击 **部署并保存配置**，保持 USB 供电。App 自动执行：

1. 核对固件项目、版本、硬件与名称；最终资源同步后，匹配 0.2.1 则跳过，否则校验预编译镜像大小和 SHA 后安装，再核对身份。不全片擦除，保留 NVS。
2. 复用或配置 Wi-Fi，通过 plaintext-only API 写入灯光绑定；不设置 API 加密。旧版本迁移行为须以 0.2.1 最终验收为准。
3. 等待至少 65 秒保存，复位并免密读回；没有密钥复制入口。

串口不可用、硬件不符或校验失败时停止，不继续写配置。目标流程不要求用户输入 key；旧加密设备的升级与记录处理仍待最终迁移证据。

### 故障排查

| 问题 | 处理 |
| --- | --- |
| 镜像缺失或校验失败 | 使用资源完整的测试包，不要替换为同版本的其他构建 |
| 旧加密设备迁移异常 | 停止并核对最终升级记录；不要自行擦 NVS 或删恢复记录 |
| 不确定是否保存 | 等待复位和读回通过，不要在安装、保存或复位时拔线 |

## 步骤 3: 在 Home Assistant 验证控灯 {#verify_ha type=manual required=true verify=true config=devices/review_ha.yaml}

本步骤仍待真实 HA 与触摸验收。

1. 确认发现的 ESPHome 设备；必要时用设备 IP 和端口 `6053` 添加。
2. 按免 API 密钥方式接入，无需复制或填写 key。
3. 允许设备执行 Home Assistant 动作。
4. 分别测试灯开关和 25%、50%、75%、100% 亮度五个触摸区，再关闭 App 复测。其它图形没有点击绑定。

### 故障排查

| 问题 | 处理 |
| --- | --- |
| 无法连接 | 核对网络、地址和固件版本；不要套用旧版加密引导 |
| 触摸或灯无响应 | 核对五个触摸区、灯实体和动作权限；坐标未修改，不能据此认为触摸已修复 |
| 屏幕不跟随灯变化 | 动态状态与亮度同步仍需 HA Blueprint 或适配 |

### 部署完成

分别记录检查、安装、保存、复位免密读回及真实控灯。0.2.1 的编译/升级/持续免密与最终 App 流程仍待验收；不沿用 0.2.0 过渡结果作为通过证据。新 Wi-Fi 表单、触摸、HA 控灯与屏幕同步继续待验收。
