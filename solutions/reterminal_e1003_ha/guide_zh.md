## 套餐: 安装与设置 {#usb_candidate}

测试顺序：**安装固件 → App 内保存配置 → 在 Home Assistant 验证控灯**。
以下配置说明适用于带内置 E1003 表单的桌面 App（contract 11）。正式候选仍禁用，等待公开契约和固件资源同步；当前人工步骤仅供审阅，不执行设备写入。

## 步骤 1: 安装面板程序 {#flash_panel type=manual required=true config=devices/review_flash.yaml}

首次安装使用统一预编译固件，无需修改配置文件或编译。已安装这份固件时，直接进入步骤 2。

### 前置条件

使用兼容的本地测试 App 和已核验的固件资源。准备好灯的实体 ID，确保它属于 Home Assistant 中支持调光的灯；电脑、面板和 Home Assistant 需在同一可达局域网。

### 接线

1. 用 USB 数据线连接 E1003 底板的 USB-UART 口与电脑，关闭占用该端口的工具。
2. 在 App 选择面板端口并安装。保持默认“不全片擦除”，全程稳定供电；写入校验通过才算安装成功。

### 故障排查

| 问题 | 处理 |
| --- | --- |
| 找不到端口 | 检查数据线，并关闭占用端口的工具 |
| 没有安装入口 | 正式候选尚未开放安装；本地测试需使用已准备的测试包 |

## 步骤 2: 在 App 内保存配置 {#configure_panel type=manual required=true config=devices/review_setup.yaml}

在 App 部署页填写内置 E1003 表单，无需打开外部网页或选择脚本路径。

| 设置 | 怎么填 |
| --- | --- |
| USB 端口 | 选择已连接的 E1003 |
| 按钮控制的灯 | 粘贴灯的实体 ID，如 `light.bedroom`；开关和四档亮度共用这盏灯 |
| Wi-Fi 名称 | 首次联网时填写；同一 App 已有设备记录且设备已联网时可留空 |
| Wi-Fi 密码 | 填写所选网络的密码；输入默认遮蔽 |

点击 **保存设备配置**，保持 USB 连接。App 会检查设备身份，生成或复用独立连接密钥，写入绑定，等待至少 65 秒，再复位并加密读回。全部通过后才算配置保存成功；密钥无需手填，成功后可用按钮复制。

### 故障排查

| 问题 | 处理 |
| --- | --- |
| 不知道灯的实体 ID | 在 Home Assistant 实体列表中复制该灯以 `light.` 开头的 ID |
| 不确定是否保存 | 等待复位和加密读回通过，不要在保存过程中拔线 |
| 已配置设备缺少密钥记录 | 回到保存过该设备记录的 App；不要通过擦除配置尝试恢复 |

## 步骤 3: 在 Home Assistant 验证控灯 {#verify_ha type=manual required=true verify=true config=devices/review_ha.yaml}

这一步需要真实 Home Assistant 和灯具，仍待实机验收。

1. 确认发现的 ESPHome 设备；未发现时，用设备 IP 和端口 `6053` 手动添加。
2. 在 App 配置面板点击 **复制加密密钥，用于添加 Home Assistant**，在 Home Assistant 粘贴。
3. 勾选 **允许设备执行 Home Assistant 动作**。
4. 测试开关和 25%、50%、75%、100% 四档亮度，再关闭 App 复测；记录灯具是否实际响应。

### 故障排查

| 问题 | 处理 |
| --- | --- |
| 无法连接 | 检查局域网、设备 IP 和连接密钥 |
| 灯没有响应 | 检查“按钮控制的灯”、调光支持和动作权限 |
| 屏幕数值未跟随灯变化 | 动态状态与亮度同步仍需 HA Blueprint 或适配，不属于已验证能力 |

### 部署完成

分别记录安装校验、复位后配置保留和真实控灯结果。当前已验证前两项；新 Wi-Fi 表单配网、真实 HA 控灯及动态屏幕同步仍待实机验收。不能以配置保存成功代替控灯验收。
