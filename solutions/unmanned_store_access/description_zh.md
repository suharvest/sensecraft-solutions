## 它做什么

门口摄像头识别人脸，活体检测通过、且人员在允许时段内、不在黑名单上，才输出一个继电器脉冲开门。识别和判定都在本地完成，断网也能开门。

## 你会得到什么

- **断网照常开门**：人脸库更新、事件上报、远程开门走网络，开门本身不依赖网络。
- **防照片、防屏幕翻拍**：活体检测强制开启（RKNN 后端除外），活体模型没加载时服务拒绝启动。
- **人脸库云端统一管理**：增删人员后下发到所有门口设备；删掉的人不会因回滚被放回来。
- **远程开门**：管理界面或 MQTT 下发开门、常开、关门指令，重复指令不会开第二次门。
- **可校验的开门记录**：每次放行和拒绝都记录，记录被篡改后校验接口会报出。

## 适用场景

- 无人/少人值守门店的员工入口、库房、后门
- 人员名单经常变的共享办公
- 需要留痕的设备间、机柜
- 门口已有 RTSP 摄像头、不想更换的站点

不适用于放错一个人就会出安全事故的门。本方案不是经过认证的安防产品。

## 实测效果

| 指标 | 效果 |
|---|---|
| 刷脸到开门信号 | **0.6 秒左右**，人脸库从 10 人增加到 1000 人基本不变慢 |
| 注册人员开门 | **24 次全部开门** |
| 陌生人 | **40 次 0 次误开** |
| 手机屏幕翻拍、屏幕静止画面 | **60 次 0 次误开** |

测试设备为 reCamera Pro，开门时间不含继电器和锁的机械动作。

## 输出接口

| 接口 | 内容 |
|---|---|
| MQTT 「access/v1/events」 | 每次放行/拒绝的判定事件 |
| MQTT 「access/v1/status/{device_id}」 | 设备在线状态与心跳 |
| MQTT 「access/v1/commands/{door_id}」 | 远程开门 / 常开 / 关门指令 |
| HTTP 「/api/…」 | 管理界面 API：人员、设备、事件、记录校验 |

## 两条路线

| | A. AI 摄像头直控 | B. AI 主机 + 现有摄像头 |
|---|---|---|
| 设备 | reCamera Pro，或标准版 reCamera | reComputer J20 / J30 / J40 / R1000 |
| 摄像头 | 设备自带 | 门口已有的 RTSP 摄像头 |
| 开门路径是否经过网络 | Pro 不经过；标准版经过 MQTT | 继电器接主机时不经过 |

**选 A**：门口还没有摄像头，想要一台设备搞定。
**选 B**：门口已有摄像头，或一台主机要管多道门。

## 使用须知

- **本方案只输出继电器干接点**，接门禁控制器的输入端。门锁和锁的电源由门禁施工方负责，不能直接用设备引脚驱动锁。
- **接线顺序：先接 LED 确认信号，再接继电器，最后接锁。**
- 有效电平、脉宽、常开/常闭触点、断电状态没有默认值，必须按现场配置。
- 识别阈值需在现场实测后调整。
- 随包的 MQTT broker 是匿名明文配置，仅供测试；正式部署需开启 TLS 与访问控制。
- RKNN 后端没有活体检测，需要防伪的场景请选其他后端。
- reCamera Pro 的云端人脸注册目前还不能产出可用的人脸库。

## 许可说明

代码为 Apache-2.0。**人脸识别模型 InsightFace buffalo_l 仅限非商业研究使用**，本包不附带模型权重。商业部署需换成可商用的模型，并重建全部人脸库。活体模型 Silent-Face-Anti-Spoofing 为 Apache-2.0，可商用。
