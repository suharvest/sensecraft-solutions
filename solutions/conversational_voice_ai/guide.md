## Preset: Cloud or OpenAI-Compatible LLM {#cloud_llm}

Speech runs on the device; replies are generated by Qwen API or the OpenAI-compatible endpoint you enter. The default is Alibaba Cloud Model Studio's Beijing endpoint with qwen3.5-flash; replace the base URL, key, and model ID for another provider.

- **Microphone:** a reSpeaker XVF3800 USB microphone array is required (a plain USB mic causes echo and false interruptions).
- **Network:** required for every conversation turn.
- **API key:** enter an API Key and a Model ID at deploy time; the model must support streaming Chat Completions.

**Optional wake word:** select **Wake word required** in the deployment form and enter a short Chinese or English phrase; a short tone plays when it is detected. **Always listening** is the default.

## Step 1: Deploy the Cloud-Backed Voice Terminal {#deploy_cloud type=docker_deploy required=true config=devices/cloud_rk3576.yaml}

After deployment, you can interrupt a spoken answer at any time.

### Target {#cloud_rk3576 type=remote device=rk3576 device_name="RK3576" config=devices/cloud_rk3576.yaml default=true}

Run speech on RK3576 and connect to a cloud or LAN model. Requires at least 12 GB free disk.

### Wiring

1. Connect the reSpeaker XVF3800 and speaker
2. Fill in the SSH details and the model endpoint settings

### Deployment Complete

Ask a question. Within one second of playback starting, speak again; the current answer should stop immediately.

### Troubleshooting

| Symptom | Action |
|-------|----------|
| API returns 401 | Confirm the API key belongs to the endpoint's region |
| Speech is recognized but no reply plays | Check the agent log for LLM request errors and confirm the model supports streaming |
| No audio after replugging the microphone | Confirm the new Agent image is running |

### Target {#cloud_local type=local device=jetson config=devices/cloud_jetson.yaml}

Deploy to this machine. It must be a Jetson Orin with JetPack 6.2, Docker, and NVIDIA Container Toolkit, and at least 15 GB free disk.

### Wiring

1. Connect the reSpeaker XVF3800 and speaker to this machine
2. Fill in the model endpoint settings and the assistant personality
3. Deploy and wait for speech model warmup

### Deployment Complete

Ask a question, then speak while the reply is playing to verify interruption.

### Troubleshooting

| Symptom | Action |
|-------|----------|
| Local deployment is unsupported | Use the remote target unless this machine is a Jetson Orin running JetPack 6.2 |
| NVIDIA runtime missing | Install NVIDIA Container Toolkit and restart Docker |

### Target {#cloud_rk3588 type=remote device=rk3588 device_name="RK3588" config=devices/cloud_rk3588.yaml}

Run speech on RK3588 and connect to a cloud or LAN model. Requires at least 12 GB free disk.

### Wiring

1. Connect the reSpeaker XVF3800 and speaker
2. Fill in the SSH details and the model endpoint settings

### Deployment Complete

### Troubleshooting

| Symptom | Action |

### Target {#cloud_jetson type=remote device=jetson device_name="Jetson Orin" config=devices/cloud_jetson.yaml}

### Wiring

1. Connect the reSpeaker XVF3800 and speaker
2. Choose the Orin Nano or Orin NX voice profile

### Deployment Complete

After warmup, complete two turns and speak during playback to verify interruption.

### Troubleshooting

| Symptom | Action |
|-------|----------|
| CUDA initialization fails | Check JetPack 6.2, TensorRT 10.3, and the container runtime |
| Orin Nano runs out of memory | Use the `jetson-qwen3asr-matcha` profile; do not start a local 4B model on Nano |

### Target {#cloud_rpi5 type=remote device=rpi5 device_name="reComputer Industrial R20 series" config=devices/cloud_rpi5.yaml}

Run speech on the CPU of a reComputer Industrial R20 series and connect to a cloud or LAN model. Requires at least 10 GB free disk. **English only**; any other language stops the deployment before services start.

### Wiring

1. Connect the reSpeaker XVF3800 and speaker
2. Fill in the SSH details and the model endpoint settings
3. Leave the conversation language on English

### Deployment Complete

Ask a question in English. Within one second of playback starting, speak again; the current answer should stop immediately.

### Troubleshooting

| Symptom | Action |
|-------|----------|
| Deployment stops with "not supported" | Select English |
| Replies are slow | Close other workloads or move to an NPU board |
| No audio after replugging the microphone | Confirm the new Agent image is running |

## Step 2: Verify Conversation and Barge-in {#verify_cloud type=web_dashboard required=true config=devices/dashboard_cloud.yaml}

Watch the listening, thinking, speaking, and barged-in states on the dashboard.

### Deployment Complete

Three normal turns plus an immediate stop when you say “wait” during playback pass this check.

### Troubleshooting

| Symptom | Action |
|-------|----------|
| State changes but there is no sound | Check that the default playback device is the speaker |
| Room noise triggers interruptions | Confirm the microphone is the reSpeaker XVF3800, then raise the client VAD threshold slightly; do not mute capture |

## Step 3: Verify the Selected Language {#voice_chat_cloud type=web_dashboard required=true config=devices/voice_chat_cloud.yaml}

Confirm that recognition and spoken replies use the language chosen at deploy time.

### Deployment Complete

#### Acceptance checklist

1. `curl -fsS http://<device-ip>:8621/health` returns success.
2. Ask one question; a spoken reply starts within a few seconds.
3. Speak again within one second of playback starting; the current answer stops immediately.
4. Two or three turns are transcribed and answered in the selected language.
5. On the device, `docker compose -p conversational_voice_ai -f ~/conversational_voice_ai/assets/docker/docker-compose.<target>.yml logs --since 10m | grep -i error` returns nothing (`<target>` is `rk3576`, `rk3588`, `jetson`, or `rpi5`).

### Troubleshooting

| Symptom | Action |
|-------|----------|
| Replies come back in the wrong language | Check the assistant personality prompt |
| Deployment never started | The selected language is not supported on this board; pick a supported one |
| Transcript language is right but audio is wrong | Report the language and the board; do not edit the speech profile yourself |

## Preset: Fully Local Conversation {#local_llm}

Speech recognition, synthesis, and the conversation model all run on the device.

- **Microphone:** a reSpeaker XVF3800 USB microphone array is required (a plain USB mic causes echo and false interruptions).
- **Network:** needed only on first deploy to pull images and models, then runs offline; no API key needed.

## Step 1: Deploy Fully Local Voice AI {#deploy_local type=docker_deploy required=true config=devices/local_orin_nx.yaml}

Deploy the speech service, local model service, and duplex agent.

### Target {#local_orin_nx type=remote device=orin_nx device_name="Orin NX" config=devices/local_orin_nx.yaml default=true}

Run Qwen3-ASR, Matcha-TTS, and Qwen3.5-4B on Orin NX 16GB. Requires JetPack 6.2 and at least 25 GB free disk.

### Wiring

1. Connect the reSpeaker XVF3800 and speaker
2. Confirm the device is Orin NX 16GB
3. Enter SSH credentials and deploy

### Deployment Complete

First model download and warmup can take several minutes. After both health checks pass, test conversation and interruption.

### Troubleshooting

| Symptom | Action |
|-------|----------|
| Model load runs out of memory | Stop other GPU containers; do not deploy to Orin Nano 8GB |
| Engine check fails | Do not mix engines built for another TensorRT/JetPack version |

### Target {#local_this_machine type=local device=orin_nx config=devices/local_orin_nx.yaml}

Deploy to this machine. It must be an Orin NX 16GB running JetPack 6.2, with at least 25 GB free disk.

### Wiring

1. Connect the reSpeaker XVF3800 and speaker
2. Stop other GPU workloads
3. Deploy and wait for the local LLM and speech service to become healthy

### Deployment Complete

After warmup, disconnect external networking and confirm conversation still works.

### Troubleshooting

| Symptom | Action |
|-------|----------|
| Local machine is not Orin NX 16GB | Choose the remote target and select the correct device |
| Model load runs out of memory | Stop other GPU containers before deploying |

### Target {#local_rk3588 type=remote device=rk3588_rk1828 device_name="RK3588 + RK1828" config=devices/local_rk3588_rk1828.yaml}

Run speech on RK3588 and Qwen3-4B on the RK1828 / RM182X card. Requires at least 18 GB free disk and an initialized RK1828 host driver and firmware.

### Wiring

1. Confirm the RK1828 has independent 12V power, a running driver service, and its device node
2. Connect the reSpeaker XVF3800 and speaker
3. Enter SSH credentials and deploy

### Deployment Complete

Confirm health checks pass on ports 1828 and 8621, then run multi-turn conversation and interruption tests.

### Troubleshooting

| Symptom | Action |
|-------|----------|
| RK1828 cannot load the model | Check host driver, firmware, and independent power; never run `rknn-smi reset` |
| The card is already in use | RK1828 runs one large model at a time; stop other RK1828 inference services |

## Step 2: Verify Local Conversation and Barge-in {#verify_local type=web_dashboard required=true config=devices/dashboard_local.yaml}

Disconnect external networking and confirm dialogue does not depend on the cloud.

### Deployment Complete

With the network disconnected, run three turns in the real room at real speaker volume. Interrupt 0.5–1 second after each answer begins; the old reply should stop immediately without losing what you said.

### Troubleshooting

| Symptom | Action |
|-------|----------|
| First offline start fails | Images and models are not fully cached; complete one online startup first |
| Replies are too long | Limit the prompt to one or two spoken sentences |
