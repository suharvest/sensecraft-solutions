## 这是什么

深度相机能告诉你物体有多远。它也更贵、需要第二个镜头或投射器，还多一样要装要标定的东西。

这个方案在你已有的 reCamera 上跑单目深度模型。输入一张普通图像，输出逐像素的稠密深度图，
全部在相机自己的 TPU 上完成。视频流右下角带一个彩色深度预览，数值走 MQTT。

## 这里的「深度」是什么意思

**是相对远近，不是米。** 模型给出场景由近及远的排序，它不测距离，输出里的任何数字都不该
当成距离读。要真正的绝对距离，需要相机标定和目标域训练，都不在本方案范围内。

但这个排序已经够回答一类有用的问题：现在有没有东西离镜头很近、画面哪一侧更近、
有没有物体进入前景。

## 真机实测

reCamera（SG2002 / CV181x），BF16 模型，655 帧样本：

| | |
|---|---|
| TPU 前向 | 19.7 ms（p95 19.8） |
| 整条逐帧路径 | 35.4 ms |
| 模型体积 / ION | 2.9 MB / 6.7 MB |
| 稳定性 | 524 帧无管线停顿 |

前向耗时逐帧抖动在 0.1 ms 以内。整条路径比模型本身长，多出来的是 CPU 侧的预处理、
统计和彩色预览。

## 哪些场景可用，哪些不行

在有真实纵深的房间里核对过：近处家具一侧显红，地面延伸和远墙显蓝，上报的 3x3 网格
与预览画出的颜色一致。

对准大面积空白天花板时可用范围会塌缩——同一台相机上，第 2 与第 98 百分位之间的跨度
从 1.72 降到 0.41。大面积无纹理表面、玻璃和天空是这类模型已知的弱项。
图库里第二张就是这个失效案例，不是好结果。

模型基于室内场景训练，室外深度范围会明显压缩。

## 你会得到什么

- **RTSP**（8554 端口），深度预览已合成进画面角落
- **MQTT**：逐帧百分位、近距离面积占比、3x3 方位近度网格，可用来判断「左侧是否比右侧近」
- **Home Assistant** 自动发现近距离面积与近距离存在两个实体
- **ONVIF**：VMS 可自动发现相机并拉流
