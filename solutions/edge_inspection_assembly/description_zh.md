> ⚠️ **随包模型训练在 DeepPCB（裸板铜箔缺陷数据集）上，不是装配缺件数据。** 真实装配场景请用自采数据（真实 PCBA + 卡尺实测值）重训。

## 方案做什么

一台摄像头盯住一个检测工位，每帧检查缺陷、缺件和尺寸公差，任一不合格即判 NG。判定同时通过 Modbus TCP 交给 PLC、通过 MQTT 交给 MES 或历史库。

## 你会得到什么

- **缺件判定**：列出哪个装配位缺件，以及多出的零件。
- **尺寸判定**：用标定物换算毫米，按名义尺寸 ± 公差给出合格、偏小或偏大。
- **PLC 直接可用**：线圈给 OK/NG，寄存器给缺件数、尺寸和公差结果；已读表面质检寄存器的 PLC 程序不用改。
- **每帧一条 MQTT 事件**：判定原因、检测框、缺件和尺寸明细，可做追溯。
- **每路相机单独配置**：缺件模板和测量区域按摄像头设置，四条 NG 规则可逐条关闭。

## 适用场景

- PCBA 与小型装配工位，固定机位能看全每个装配位。
- 需要按图纸公差确认零件尺寸的来料或出货检验。
- 已在用 OK/NG 线圈、想拿到原因码的 PLC 产线。

## 输出接口

| 接口 | 内容 |
|---|---|
| MQTT 「<设备名>/inspection/<流编号>/results」 | 每帧判定、原因、检测框、缺件与尺寸明细 |
| Modbus TCP 502 | 线圈 0 NG / 线圈 1 OK；HR 0–7 缺陷信息，HR 8–11 缺件数、多余件数、尺寸毫米 ×100、公差判定码 |
| HTTP 8080 「/healthz」 「/events」 「/preview.mjpg」 | 健康计数、最近事件、带框与缺件区域的实时画面 |

「HR 10 = 0」 不代表量到 0 mm，需先读 HR 11 的公差判定码。

## 使用须知

- 缺件模板区域按画面坐标定义，摄像头移动或重新对焦后必须重建；先固定机位再建模板。
- 随包缺件模板是示例，上线前换成自己产品的装配位。
- 尺寸测量要求单一平面：零件倾斜、标定物与被测面不等距、边缘对比度低都会导致误差或测不到。
- 线圈与寄存器分两次读取时可能跨两次判定；先读寄存器，把线圈当触发信号。
- 多路共用一组寄存器，只保留最新判定；逐路结果从 MQTT 取。
- 随包 MQTT broker 为本机匿名，生产环境改用带凭据的 broker。
