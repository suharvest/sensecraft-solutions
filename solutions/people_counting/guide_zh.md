## 套餐: Grove Vision AI Module V2 {#grove_vision_ai_v2}

把一块 Grove Vision AI Module V2 变成独立的人流计数器。模组自己完成人体检测、跨帧跟踪、双向越线计数，并实时给出每个区域内的人数——全部在模组本地算完。

| 设备 | 用途 |
|------|------|
| Grove Vision AI Module V2 | 摄像头 + Himax WE2（Cortex-M55 + Ethos-U55 NPU），全部计算在设备本地完成 |
| USB-C 数据线 | 烧录与实时预览 |

**你会得到：**
- 最多 4 条计数线，各自独立统计进/出
- 最多 4 个区域，实时显示区域内人数
- 人体检测与多目标跟踪运行在 NPU 上
- 不联网、不上云——画面只经 USB 线传到你自己电脑上的应用，不去别处

**真机实测：** 单帧推理 48 ms，端到端约 13 fps（240x240 输入，Swift-YOLO Nano 单类别人体模型，INT8 量化后 mAP 92.6%）。

**前置条件：** 一台有空闲 USB-C 口的电脑。不需要 WiFi、不需要账号、不需要服务器。

## 步骤 1: 烧录固件与模型 {#grove_himax type=himax_usb required=true config=devices/grove_himax.yaml}

把人流计数固件和人体检测模型写入模组。

### 接线

1. 用 USB-C **数据线**把 Grove Vision AI Module V2 连到电脑（只能充电的线不会枚举出串口）
2. 串口通常会自动选好。如果没有，选 CH343 端口——macOS 上形如 `/dev/cu.usbmodem*`，Linux 上是 `/dev/ttyACM0`，Windows 上是名字带 `USB-Enhanced-SERIAL CH343` 的 COM 口
3. 点击 **烧录**

烧录会写入两样东西：先是固件镜像，然后是烧到 flash 地址 `0x700000` 的人体检测模型。模型文件尾部带有 16KB 填充——这是有意为之，用于绕过 xmodem 传输在距文件末尾约 6KB 处的截断问题。921600 波特率下整个传输需要几分钟。

### 故障排查

| 问题 | 解决办法 |
|------|---------|
| 列表里没有串口 | 换一根能传数据的 USB-C 线，或换一个 USB 口 |
| 烧录一直不开始 | 拔掉重插模组后重试 |
| 烧录中途卡住 | 关掉其它占用串口的程序（串口助手、另一个 IDE），重新连接后重试 |
| 烧录完成但下一步没有画面 | 拔插一次模组，让新固件干净启动 |

## 步骤 2: 配置计数区域 {#counting_panel type=serial_camera required=true config=devices/counting_panel.yaml}

在实时画面上画出计数线和区域，然后看着计数更新。

### 使用方法

1. 点击 **连接**——模组会加载人体检测模型并开始推流。模型加载需要几秒，第一帧会稍慢
2. 你会看到 240x240 的实时画面，每个检出的人身上带一个框
3. 用视频下方的 **计数** 面板画线和区域

### 画一条计数线

1. 在计数面板点击 **添加计数线**
2. 在画面上拖出你想要的边界——门口、通道口、楼梯顶端
3. 线会分出 **进** 和 **出** 两侧；方向反了就把它调换过来
4. 走过这条线，看进/出计数是否累加

最多支持 4 条线，每条线各自维护自己的进/出计数。

### 画一个区域

1. 在计数面板点击 **添加区域**
2. 在你关心的范围上拖一个矩形——排队区、等候区、会议桌
3. 区域会显示当前在其中被跟踪到的人数

最多支持 4 个区域。

### 选择跟踪锚点

每个被跟踪的人会被归约成一个点，越线判定和区域判定都基于这个点。**锚点模式** 决定用哪个点：

| 锚点 | 建议用于 |
|------|---------|
| 框中心 | 平视安装，以及垂直俯视安装 |
| 框底边中心（脚） | 倾斜俯视安装 |

倾斜俯视时建议用底边中心锚点。用框中心的话，人走近摄像头时检测框会变大，中心点随之在画面里移动，可能扫过附近的计数线，触发一次并没有发生的越线。脚部锚点则稳定停在地面平面上。

### 安装建议

以下是起点建议，不是承诺——具体高度和角度取决于你的天花板和人流情况。

- **倾斜俯视**（摄像头斜向下对着通行路径）是常规选择。人体保持在检测模型训练时常见的姿态下，配合脚部锚点使用。
- **垂直俯视**（摄像头直对地面）人与人之间的遮挡最少，在密集人流下有帮助。代价是：模型是用常规视角数据训练的，正上方俯视的检出率可能下降。定版前请在你自己的场地实测。
- 计数线不要贴着画面边缘，让人在线的两侧都能被跟踪若干帧。
- 光照均匀比光照强更重要。被摄者背后有窗户或门形成强逆光，是最常见的失败场景。

### 故障排查

| 问题 | 解决办法 |
|------|---------|
| 提示"请先完成步骤 1" | 回到步骤 1 选好串口 |
| 画面一直是黑的 | 重新插拔 USB 线，再点连接 |
| 完全没有检测框 | 确认步骤 1 的模型烧录成功；不确定就重烧一次 |
| 人走向摄像头时计数忽增忽减 | 把锚点切换成框底边中心（脚） |
| 同一个人被数了两次 | 把计数线往画面中间挪，让轨迹在线两侧都稳定 |
| 进和出反了 | 在计数面板里翻转这条线的方向 |

### 部署完成

模组已经在计数了。以上一切都在模组本地运行——应用只是把它报上来的结果显示出来。

**试一试：**
1. 沿一个方向走过计数线，再反向走一次——进和出应各累加一次
2. 站进一个区域，观察区域人数
3. 叫上第二个人一起进画面，看多目标跟踪

**数据去哪了：** 计数事件和逐帧检测结果以 SSCMA JSON 从 USB 串口输出，你可以接进自己的脚本、看板或网关。实时预览走的是同一条 USB 串口：模组随每次结果附带一张 JPEG，应用才能把你画的线和区域叠在真实画面上。这些都只在模组和这台电脑之间传输：不上传任何数据，画面也不会进入网络或云端。
