## 这个方案能帮你做什么

你想知道今天上午有多少人进了店、现在排队的有几个人、会议室到底有没有人。常规做法是一台摄像机、一根网线、一台服务器，还有一路离开现场的视频流。

这个方案用一块摄像头模组加一根 USB 线就能做到。Grove Vision AI Module V2 完成人体检测、跨帧跟踪，统计每次穿过你画的计数线的行为，并给出你画的区域里当前站着几个人。画面只走 USB 线：帧直接传到你自己电脑上的应用做实时预览，不经网络、不经云端。

## 核心价值

| 好处 | 具体说明 |
|------|---------|
| 全部本地计算 | 检测、跟踪、计数都跑在 Himax WE2 及其 Ethos-U55 NPU 上 |
| 不联网、不上云 | 计数结果、检测坐标和预览画面都只走 USB 线，不上传任何数据 |
| 自己画几何 | 最多 4 条计数线（各自进/出计数），最多 4 个区域（实时人数） |
| 零基础设施 | 不联网、不要服务器、不要账号——一根 USB 线就是全部安装工作 |
| 数据开放 | 串口输出 SSCMA JSON，方便接进你自己的脚本或网关 |

## 适用场景

| 场景 | 怎么用 |
|------|--------|
| 店铺入口 | 在门口横一条计数线，得到分方向的进出客流 |
| 排队监测 | 在排队区域画一个区域，得到实时人数，用于调度人手 |
| 会议室 / 办公室 | 用区域判断房间是否真的有人，不依赖预定系统 |
| 走廊与楼梯人流 | 沿通行路径布多条线，看清人流朝哪个方向走 |
| 展位 | 展位周围画区域测停留，入口处画线测到访 |

## 实测性能

| 指标 | 数值 |
|------|------|
| 单帧推理 | 48 ms |
| 端到端吞吐 | 约 13 fps |
| 输入分辨率 | 240 x 240 |
| 模型 | Swift-YOLO Nano，单类别（人） |
| 模型精度 | INT8 量化后 mAP 92.6% |
| 运行于 | Ethos-U55 NPU（Vela 编译） |

以上为模组真机实测数据。实际计数准确度取决于你的安装方式、光照和人流密度——参考下面的安装建议，并在你自己的场地上验证。

## 使用须知与限制

| 条件 | 说明 |
|------|------|
| 硬件 | 一块 Grove Vision AI Module V2 和一根 USB-C 数据线，此外无需其它设备 |
| 计数线 | 最多 4 条，每条独立统计进和出 |
| 计数区域 | 最多 4 个，每个实时显示区域内人数 |
| 光照 | 正常室内光线即可。被摄者背后强逆光是最常见的失败场景 |
| 密度 | 跟踪基于逐帧关联；密集人群中的严重遮挡会损失准确度 |
| 尚未实测 | 与人工真值对比的计数准确率，以及垂直吊顶俯视安装下的检出召回率，都还没有测过 |

## 安装建议

以下结论来自模型与跟踪器的工作方式，请当作待验证的起点，而不是保证生效的配置。

- **倾斜俯视** 是常规选择——人体保持在检测模型训练时常见的视角下。把跟踪锚点设为 **框底边中心（脚）**。用框中心的话，人走近摄像头时检测框会变大，锚点随之移动扫过附近的计数线，会触发一次并没有发生的越线。
- **垂直俯视** 人与人之间的遮挡最少，密集人流下有帮助。代价是模型用常规视角数据训练，正上方俯视的检出率可能下降。定版前请先实测。
- 计数线不要贴着画面边缘，让每条轨迹在线的两侧都保持稳定。
