## 这套参考设计是什么

门店里的对话由 reSpeaker 麦克风采集并转成文字，存进零售语音后台，可查询、导出和删除。两个套餐共用同一套采集硬件和语音服务，都需要部署零售语音后台。

## 两种部署方式

**客户端转录并上传**：边缘设备在本地转写，离线时缓存，联网后把文本上传后台。

**Clip + 手机服务端转录**：reSpeaker Clip 录音经 SenseCraft Voice App 上传给平台 ASR，后台脱敏后保存。

| | 设备本地转写 | 服务端栈 |
|---|---|---|
| 采集 | 盒子上的 reSpeaker XVF3800 | 同一只阵列，或 Clip + 手机 App |
| 删除 | 自行按目录清理 | 一次调用删除数据库、对象存储与声纹 |
| 板卡 | CM4、RK3576、RK3588、J3011、J4012 或 R2000（CPU/Hailo） | 同样的 ASR 主机，加 Clip + 手机采集 |
| 部署耗时 | 约 40 分钟 | 约 60 分钟 |

采集侧相同，从本地套餐换到服务端栈不用换麦克风和板子。

## 你会得到什么

- **断网不丢记录**：后台暂时不可达时设备继续转写，恢复后补传。
- **入库前脱敏**：手机号、身份证号、姓名、地址替换成「[[PHONE]]」「[[NAME]]」等占位符，原文不写入数据库。
- **按人彻底删除**：按主体、设备或会话一次删除数据库记录、音频和声纹，并返回残留数。
- **按人导出**：导出脱敏文本和音频清单，用于回应访问与携带请求。
- **可接入 App 的 ASR 端点**：WebSocket 收 PCM，逐句返回带说话人字段的文字。
- **三档权限**：viewer 查看，operator 上报，admin 删除与导出。

## 适用场景

- 单店或试点门店，录音不离开边缘设备，只上传文字。
- 上行不稳定的地下商铺、临时柜台、厂区办公室。
- 想知道顾客问了什么、不想留下是谁问的门店（服务端栈套餐）。
- 需要真正删除数据来回应删除请求的部署。
- 已有手机 App 采集、缺后端链路的场景。

## 实测效果

| 指标 | 效果 |
|---|---|
| 说完话到出最终文字 | **p50 861 ms / p95 1027 ms**（reComputer RK3576） |
| 中文流式识别错误率 | **CER 9.4%**（reComputer RK3576） |
| 删除某人记录后残留数据 | 数据库、对象存储、本地音频均为 **0** |
| 个人信息脱敏识别率 | **precision 0.98 / recall 0.95** |
| 角色不足时拒绝访问 | **通过**：缺凭据 401、档位不足 403 |

语音数字为文件喂入 RK3576 板测得，脱敏分数在 114 条中英文书面文本上测得；适用条件为稳态背景噪声 **不高于 70 dB**、说话人距阵列 **约 3 m 以内**。

## 输出接口

| 接口 | 内容 |
|---|---|
| 设备 「ws://<设备IP>:8621/asr/stream」 | 流式转写：送入 PCM，返回文字 + 标点 + 声纹向量 |
| 设备 「http://<设备IP>:8090/」 | 本地网页：实时转写、麦克风状态、声纹注册库 |
| 服务端 WebSocket 8080 「/ws?token=<operator>」 | App 上传 PCM，逐句返回转写 |
| 服务端 HTTP 8081 「/api/v1/recordings」 | 转写上报与查询 |
| 服务端 HTTP 8081 「/api/v1/privacy/erase」、「/api/v1/privacy/export」 | 按主体删除 / 导出（仅 admin） |
| 服务端 HTTP 3000 「/」 | 管理后台 |

## 使用须知

- 在门店录音是否合法、需要给出什么告知由部署方负责；本方案不是合规认证。
- 声纹匹配是本地相似度归类，不能当身份核验。
- 4 GB 板子同时开标点和声纹会压缩内存余量，可分别关闭。
- 设备本地转写目录不会自动轮转，需自定保留期并定期清理。
- 开启音频文件输出会在设备上保留真实人员录音，只要文字就关闭。
- 「voice-client:c4-local」 镜像未发布，新板子需自行构建。
- 服务端栈镜像仅 arm64，换主机类别需自备对应 ASR 镜像。
- ASR 端点令牌在 URL 中，出可信局域网需在前面终结 TLS。
- 后台账号默认 viewer，需用 admin 凭据调改角色接口提权。
- 说话人识别默认关闭，按主体删除时没有声纹可删。
- 容量先按 1–2 路并发试点，实测后再扩。
