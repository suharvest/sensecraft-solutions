# 零售语音本地转写

## 这个方案做什么

一只 reSpeaker XVF3800 麦克风阵列把一路 16 kHz 单声道音频送进门店里的小型边缘盒子。盒子自己完成语音识别，每断出一句就往本机磁盘上的目录里写一个 JSON 文件。没有云端账号，不上传，镜像和模型就位之后不需要对外连接。

## 你会得到什么

- **单机闭环。** 采集、端点检测、转写、标点恢复和可选的声纹匹配都在同一台盒子里完成。拔掉网线，转写照常进行。
- **数据留在录制的地方。** 转写结果写进你指定的目录。音频是否保留是一个开关：可以留下 WAV 片段，也可以只留文字。
- **两个硬件档位。** reRouter CM4 是最便宜的纯 CPU 安装；reComputer RK3576 让 NPU 承担语音识别，把 CPU 空出来。
- **不依赖云端身份服务的说话人标签。** 语音服务每句返回一个 192 维 CAM++ 向量，与本地注册库的匹配在同一台设备上完成，也可以整个关掉。
- **占用有界。** compose 里限制了容器日志大小，模型放在命名卷里，随使用增长的只有转写目录。

## 适用场景

- 单店或试点门店，不希望录音离开现场。
- 上行链路不可靠的环境——地下商铺、临时柜台、厂区办公室。
- 采购规定禁止第三方处理语音，只接受本地文本文件作为产物。
- 上云之前的前置步骤：先在现场把音频通路和识别质量验证清楚。

## 实测边界

这不是经过认证的转写产品，也不是合规控制手段。它产出的是下表所示质量的文本，这些文本不具备法律效力。在门店录音是否合法、需要给出何种告知，由你自行负责。

下面每个数字都在 OpenVoiceStream 语音服务（本方案部署的就是它）上、按标注条件实测得到，没有一条是从相近板卡推算的。

另有两条不是性能数字、但直接决定站点能不能用的边界：

- **背景噪声不高于 70 dB**，即正常说话的音量。超过这个水平，阵列的噪声抑制无法再把说话人从环境中分出来，词错率会在上表任何数字生效之前先劣化。
- **说话人距阵列约 3 m 以内**。这是 XVF3800 波束成形在门店里能覆盖的范围；再远，换哪块算力板都救不回来。

## 输出接口

| 接口 | 位置 | 内容 |
|---|---|---|
| 转写文件 | 设备上的 `<输出目录>/cache/asr/<id>.json` | 每断出一句一个 JSON：文本、时间戳、语种，开启声纹时带说话人标签 |
| 音频片段 | `<输出目录>/voice/*.wav` | 16 kHz 单声道 WAV，仅在开启文件输出时写入 |
| 流式 ASR | `ws://<设备IP>:8621/asr/stream` | 送入 PCM，返回转写 + 标点 + 192 维向量 |
| 离线 ASR | `POST http://<设备IP>:8621/asr` | 整文件转写；验收步骤用的就是它 |
| 本地网页 | `http://<设备IP>:8090/` | 实时转写、麦克风状态、声纹注册库 |

这张表里没有任何一条会离开设备。没有配置上行地址，也没有需要填的凭据。

## 套餐对比

**reRouter CM4（CPU）。** 把本地转写放进门店的最便宜做法。Paraformer 流式 ASR 跑在 4 个 Cortex-A72 核上，支持中英文，不需要加速器。预算是主要约束、且现场只有一个说话区时选它。它在这块 SoC 上的 ASR 速度和准确率尚未实测——批量铺开前先做试点。

**reComputer RK3576（NPU）。** SenseVoice 跑在 6 TOPS NPU 上，CPU 因此能同时承担标点恢复、声纹向量和采集客户端。实测离线 RTF 0.26，全部加载占 1.71 GiB。想要上表的实测数字而不是估计值、或者打算同时开标点和声纹时选它。

两个套餐部署的是同样两个容器，产出同样布局的同样文件。切换套餐改的是镜像 tag 和 profile，不改输出格式。

## 使用须知

- **整套栈是单点。** 一台盒子、一只麦克风。设备关掉就什么都采不到，而且没有服务端的断档检测来提醒你。
- **转写目录会无限增长。** 没有任何轮转机制。在部署跑上几个月之前，先定好保留期，用 cron 或运维流程执行。
- **是否保留音频是一个明确的选择。** 开着文件输出便于复核，同时也意味着设备上留着真实人员的录音。只要文字就把它关掉。
- **声纹匹配是本地的启发式方法。** 它按固定阈值把相似声音归到注册库里，不是身份核验，绝不能当身份核验用。
- **标点和声纹各自加载一个模型。** 在 4 GB 板子上两个都开会压缩余量；设备输入项里可以分别关闭。
- **不包含任何云端路径。** 如果门店之后需要多店看板、导出或硬删除流程，那是另一个方案包——本方案没有可指向的上行服务。
- **2026-09-06 的 RK3576 打包验证测的是 SenseVoice 识别与推理链路，不是 reSpeaker XVF3800 的采音通路。** 验证用的板子上没有接实体 XVF3800，5 条验收短句都是以文件方式喂入的（`POST /asr` 与 `/asr/stream`），没有经过真实麦克风。"PCM 音频到达语音服务"之后的部分已在真机确认；阵列自带的波束成形/回声消除和客户端的 ALSA 采集本次没有被实测覆盖。
- **`voice-client:c4-local` 镜像仍未发布。** RK3576 故障排查表里给出了一个真机确认可用的替代 tag（`sensecraft-voice-client:ovs-20260901b`），但它没有推送到任何 registry——新板子仍然需要自己构建，或拿到那个 tag 的拷贝。

## 许可说明

语音服务内含第三方模型——识别用 SenseVoice 和 Paraformer，标点用 CT-Transformer，声纹用 CAM++，端点检测用 Silero VAD。各自遵循其上游许可，商业使用需你与相应上游自行确认；本方案既不授予也不扩展任何相关权利。模型在首次启动时从部署时选定的镜像源下载。
