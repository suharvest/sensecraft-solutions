## 这个方案能帮你做什么

停车场要知道哪个车位有车，常见做法是每个车位装一个地磁或超声波检测器，布线和维护成本都高。这个方案直接用场内已有的 IP 摄像头：一路摄像头能看到多少个车位，就能同时检测多少个。你在网页上给每个车位画一个框，边缘主机就持续判断框里有没有车，把每个车位「占用 / 空闲」的状态发到你的系统里，用于余位屏、导航指引或计费。

## 核心价值

| 好处 | 具体说明 |
|------|---------|
| 不加车位检测器 | 一路摄像头覆盖它能看到的所有车位，不用逐位安装、布线 |
| 状态变化几秒内上报 | 车停稳约 3 秒后标为占用，车离开约 5 秒后标为空闲 |
| 车位自己画 | 在网页上对着实时画面给每个车位画框、命名，保存后立刻生效，重启后保留 |
| 视频不出场地 | 画面在现场的边缘主机上分析，对外只发车位状态，不上传视频 |
| 摄像头断了能看出来 | 某路摄像头断流约 10 秒后，它下面的车位标为「未知」，不会继续报旧状态 |

## 适用场景

| 场景 | 怎么用 |
|------|--------|
| 地下车库余位屏 | 每层几路摄像头，汇总各层空闲车位数，显示在入口和各层余位屏上 |
| 商场 / 写字楼停车场 | 按区域统计空位，引导车辆去还有空位的区域 |
| 专用车位管理 | 给充电桩车位、访客车位单独画框，被占用时通知管理员 |
| 车位利用率统计 | 记录每个车位的占用时长，分析高峰时段和长期闲置车位 |

## 部署后你会得到什么

- **车位编辑页**：浏览器打开，选择摄像头，在画面上点几下画出车位、填上车位编号（如 B1-023），保存即生效。
- **车位状态消息**：每路摄像头一个 MQTT 主题 `<站点编号>/parking/<摄像头编号>/slots`。任何车位状态变化时，发一条消息，包含这路摄像头下每个车位的状态（`occupied` 占用 / `free` 空闲 / `unknown` 未知）以及占用、空闲、未知的车位数。你的余位屏、停车管理系统或 Home Assistant 订阅这个主题即可。

## 使用须知

### 核心硬件设备

| 设备 | 说明 | 必需 |
|------|------|------|
| reComputer J30 / J40（Jetson Orin Nano / Orin NX，JetPack 6.2） | 运行车位检测；必须是 Jetson Orin Nano 或 Orin NX 模组，系统为 JetPack 6.2 | 二选一 |
| reComputer RK3588 | 运行车位检测，用板载 AI 加速芯片 | 二选一 |
| IP 摄像头 | 现场已有的摄像头即可，需能输出 H.264 编码的 RTSP 视频流 | ✓ 必选 |
| MQTT 服务器 | 接收车位状态，例如现场已有的 Mosquitto | ✓ 必选 |

实测表现（每路摄像头每秒分析 1 帧）：

| 边缘主机 | 单帧分析耗时 | 多路摄像头 |
|------|------|------|
| reComputer J30（Jetson Orin Nano） | 约 6.5 ms | 6 路同时运行，每路每秒 1 帧，无丢帧 |
| reComputer RK3588 | 约 37 ms | 接入多路时逐路增加，确认每路都在更新状态 |

### 网络要求

- 边缘主机、摄像头和 MQTT 服务器在同一局域网，边缘主机能访问摄像头的 RTSP 地址（通常是 554 端口）。
- 部署时边缘主机需要能上网，用于下载运行程序和识别模型；部署完成后可断网运行。
- 你的电脑需要能访问边缘主机的 8080 端口（车位编辑页）。

### 摄像头要求

- 摄像头从高处斜向下拍，每个车位在画面里能被看清，不被相邻车辆完全挡住。
- 一个框只框一个车位。车停进去后，车身要占到框面积的三分之一左右才会判为占用；框住好几个车位或很远处小车的大框不会判为占用。
- 用摄像头的子码流即可，H.264 编码。
