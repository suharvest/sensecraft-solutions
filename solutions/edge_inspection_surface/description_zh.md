## 这个方案做什么

固定相机对着钢带或工件，设备逐帧识别六类表面缺陷（crazing、inclusion、patches、pitted_surface、rolled-in_scale、scratches），把 OK/NG 判定同时通过 Modbus TCP 线圈和 MQTT 交给产线。全部在设备本地完成，图像不出设备。

## 你会得到什么

- **PLC 直接可用的判定**：线圈 0 为 NG、线圈 1 为 OK，寄存器里带缺陷类别、数量和位置。
- **每帧一条 MQTT 结果**：判定、理由和全部检测框。
- **本地调试页**：带框实时画面、耗时与计数、最近判定。
- **一台主机多路相机**：10 FPS 下稳定 8 路。
- **可选异常检测**：只用无缺陷图训练，标出未学过的缺陷区域。

## 适合接到哪里

- 带钢与卷板表面检测，判定接到剔除或打标工位。
- PLC 驱动的老产线改造，只需对接 Modbus。
- 正式部署前录制产线数据，用于重新标注和定阈值。

## 检测器选型

| 模型 | 整帧漏检（290 帧） | CPU 时延 | Hailo-8 |
|---|---|---|---|
| YOLOX-Tiny（默认） | **7 帧** | 基准 | 支持 |

在 「config/config.json」 的 「model.track」 里切换。

## 无监督异常检测（可选）

EfficientAD-S 只用无缺陷参考图训练，标出与参考图不像的区域，结果作为独立的 「anomaly_score」 字段，不改变 OK/NG 判定。适合看区域热力图，不适合作为整帧开关；启用前需用现场相机采集 OK 样本并重新标定 「anomaly.threshold」。

## 输出接口

| 接口 | 内容 |
|---|---|
| Modbus TCP 502，线圈 0-1 | NG / OK 判定 |
| Modbus TCP 502，HR 0-7 | 缺陷类别、数量、主缺陷位置、心跳 |
| MQTT 「<设备名>/inspection/<流编号>/results」 | 每帧判定、理由与检测框 |
| HTTP 8080 「/preview.mjpg」、「/healthz」、「/events」、「/snapshot.jpg」 | 实时画面、健康计数、最近判定 |

## 使用须知

- 阈值需按业务定：从 0.35 提到 0.6，精确率 0.765→0.865，整帧漏检从 7 帧增到 39 帧。
- 验证集每张图都有缺陷，误报率需用自己的产线图像测。
- 部署步骤只配置一路相机，其余路加到设备上的 「streams」 列表后重启容器。
- 多路共用同一组 Modbus 寄存器，最后一次判定生效；逐路结果从 MQTT 取。
- 实测输入是合成视频，定路数前用自己的视频源压测。
- 随包 MQTT broker 为匿名调试用，生产环境改用带凭据的 broker。
