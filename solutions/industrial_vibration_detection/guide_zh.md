## 套餐: 离网自组网通讯 {#offgrid_mesh_communication}

出厂开箱即用体验——T1000-E 已预置 Meshtastic 固件，无需连接电脑烧录。长按开机后直接使用手机 App 蓝牙绑定，在无蜂窝信号和外网覆盖环境下实现多节点自组网、文本互发与位置共享。

| 设备 | 用途 |
|---|---|
| SenseCAP T1000-E | 离网通信终端与中继节点，内置 LoRa 射频、BLE 与 GPS 定位 |
| 智能手机（iOS / Android） | 运行 Meshtastic 官方客户端，通过低功耗蓝牙与 T1000-E 交互 |

---

## 步骤 1: 开机并使用手机 App 蓝牙绑定 {#pair_mesh_app type=manual required=true}

设备出厂已预置 Meshtastic 固件，无需插电脑烧录。开机后直接在手机 App 中配对。

### 接线

1. **设备开机**：长按 T1000-E 正面按键 3 秒，听到蜂鸣器鸣响一声，指示灯蓝绿交替闪烁，表示设备已开机并启动蓝牙广播；
2. **下载 App**：在手机应用商店（Apple App Store 或 Google Play / APKPure）搜索并下载官方 **Meshtastic** 客户端；
3. **开启蓝牙扫描**：打开手机蓝牙，启动 Meshtastic App，进入设备扫描列表；
4. **配对绑定**：在设备列表中找到形如 `Meshtastic_xxxx` 的条目，点击连接并同意手机弹出的系统蓝牙配对请求；
5. **设置频段与名称**：连接成功后，在 App 底栏进入 **Settings (设置) → LoRa**，将 **Region (区域频段)** 设置为与你的硬件一致的频段（如中国大陆选 `CN` 或 `470MHz`，北美选 `US`，欧洲选 `EU_868`），并可在 **User** 设置中为节点设置个性化昵称。

### 故障排查

| 现象 | 处理 |
|---|---|
| 搜不到设备蓝牙 | 确认长按按键 3 秒开机；若无指示灯反应，请先用磁吸线充电 30 分钟后再试 |
| 蓝牙配对被拒或超时 | 在手机系统设置中找到蓝牙，忽略该设备后回到 Meshtastic App 重新发起配对 |
| 提示频段未设置 (Region Unset) | 必须在 App 设置中选择正确的国家/地区 LoRa 频段，设备才能开启射频收发 |
| 误刷其他固件想恢复 | 可使用磁吸线连接电脑，通过 [flasher.meshtastic.org](https://flasher.meshtastic.org/) 网页端一键刷回官方固件 |

## 步骤 2: 离网文本通讯与节点拓扑验证 {#verify_mesh_chat type=manual required=true verify=true}

测试在完全断开外网时的自组网收发能力与节点拓扑。

### 接线

- **双机链路闭环（推荐）**：若现场有第二台 Meshtastic 节点（或同伴手机绑定了同频段节点），确认两端设置相同频段与默认频道；在接收端手机 App 上观察实时接收到的文本广播。
- **单机基线验证**：若当前仅有一台设备，主要通过本地空口广播对勾标记、节点信标发射以及离网 GPS 地图验证终端正常工作。

1. **断开外网验证**：关闭手机的 Wi-Fi 与蜂窝移动数据，确保手机处于完全离网状态；
2. **发送广播消息**：在 Meshtastic App 的 **Messages (消息)** 页面选择公共主频道（Primary Channel），输入一段文字（例如 `Hello Meshtastic from T1000-E`）并点击发送；
3. **确认发送状态**：消息右侧出现云朵或对勾标记，表示消息已通过 T1000-E 的 LoRa 射频在空中广播送达；接收端节点（若有）将实时同步显示；
4. **查看节点列表 (Nodes)**：点击底栏 **Nodes**，查看当前局域 Mesh 网络中发现的其他节点、信号信噪比（SNR）、接收信号强度（RSSI）与跳数（Hops）；
5. **离网地图与定位 (Map)**：点击底栏 **Map**，若设备处于开阔室外，GPS 锁定后可在离网离线底图上实时显示自身与对端节点的物理位置坐标。

### 故障排查

| 问题 | 解决方法 |
|---|---|
| 消息没有送达标记 | 两个节点需要使用相同的区域（Settings -> LoRa）和相同的默认频道。请确认 T1000-E 已设置区域。 |
| 节点列表中没有邻居 | 只有在第二个节点处于射频范围内时才会出现邻居；只有一个节点时，请改为核对节点信标与消息的空中发送标记。 |
| 地图上没有位置 | GPS 定位需要开阔天空，请在室外测试。 |

### 部署完成

你已成功建立了开箱即用的离网 LoRa Mesh 自组网节点，可在完全无基站的环境下进行数公里的远距离应急文本通讯与位置追踪。

## 步骤 2: 机械表面刚性贴合安装 {#mount_device type=manual required=true}

振动异常检测依赖安装接触刚度与机械振动传导。必须先将设备牢固固定在被测机械结构上，再进行基线学习。

### 安装要求

1. **避免吸震材料**：禁止使用发泡海绵胶带（海绵阻尼会显著衰减高频冲击微震）；
2. **推荐粘接介质**：使用 **3M VHB 4910（0.5mm 亚克力双面胶）** 或强力金属磁吸底座；
3. **测点位置**：选择电机、风机或水泵轴承座的主振动径向受力平面，确保贴合表面无油污杂质；
4. **安装方向**：使设备平整压实于金属表面；贴好后连接磁吸数据线，保持通电准备标定。

### 故障排查

| 问题 | 解决方法 |
|---|---|
| 正常运行时误报或始终不报警 | 软泡棉或海绵胶会衰减高频振动。请在干净、无油脂的平整表面使用 3M VHB 4910 或磁吸底座。 |
| 标定后移动了设备 | 基线是在安装位置学习的；更换安装位置后需重新执行步骤 3。 |

---

## 步骤 3: 运行工况在线标定与基线训练 {#vibration_calibration type=vibration_calibrator required=true config=devices/vibration_calibrator.yaml}

设备贴合就位后，保持磁吸数据线连接电脑，启动被测机械设备，在健康运转工况下使用原生标定控件完成基线训练。

### 接线

1. **连接串口**：确保磁吸数据线已将 T1000-E 连接至电脑，在标定控件中选择对应的串口并连接（波特率 115200）；
2. **时域波形监控**：启动被测旋转机械进入平稳工况，在原生标定器界面中实时观察三轴加速度时域波形图，确认信号平稳、无外界瞬时干扰；
3. **10秒 GEDAD 基线训练**：点击 **「开始标定 / 训练基线」**，保持机械恒速运转 10 秒；系统通过 GEDAD 异常检测算法自动计算三轴加速度统计特征均值与方差门限（3.0σ），并自动将基线参数下发至设备；
4. **敲击验证**：基线训练完成后进入验证阶段，轻敲机械表面或测试台模拟振动突变，观察标定控件实时曲线是否触发峰值告警并标记异常；
5. **断开进入巡检**：验证无误后，在控件中点击断开连接，拔下磁吸数据线，设备脱离配置模式进入独立低功耗巡检。

### 故障排查

| 问题 | 解决方法 |
|---|---|
| 无法读取到串口数据波形 | 确认磁吸线已吸附在 T1000-E 背面引脚且使用的是数据线；检查串口是否被其他终端占用，波特率设置为 115200。 |
| 基线训练提示噪底漂移过大 | 确认设备通过 3M VHB 硬质胶牢固贴合在金属表面；确保 10 秒训练期间被测机械处于稳定工况，避免外界干扰。 |
| 敲击验证未触发异常 | 检查敲击力度与测点位置，或在标定控件中确认当前门限系数（默认 3.0σ）；必要时重新执行 10 秒基线采样。 |

---

## 步骤 4: 离网设备告警链路验证 {#verify_vibration_alert type=manual required=true verify=true}

完成标定后拔除数据线，在离网环境下验证异常告警链路。

### 接线

1. **进入巡检状态**：拔掉磁吸线后，T1000-E 进入超低功耗周期性振动特征监测状态；
2. **模拟机械异常**：在被测设备运转时人工施加微小冲击或偏心振动（或在测试台上轻敲轴承座附近）；
3. **接收告警报文**：端侧算法判定超过学习基准门限后，自动唤醒射频，封装设备异常告警报文注入 Meshtastic 广播；
4. **手机端验证**：现场运维人员打开手机 Meshtastic App，在消息频道中即可直接接收到设备弹出的振动异常告警、设备编号与对应 GPS 坐标。

### 故障排查

| 问题 | 解决方法 |
|---|---|
| 手机收不到告警 | 确认步骤 3 已完成、磁吸线已拔下，且手机连接的节点与第一个套餐使用相同的区域和频道。 |
| 敲击未触发告警 | 只有振动偏离已标定的基线时才会告警；加大冲击或偏心负载，或重新执行步骤 3。 |

### 部署完成

你已完成了从纯离网自组网通讯到端侧设备智能告警的完整闭环，在完全无外网覆盖的工业现场实现了低成本、长续航的预测性维护预警。

## 步骤 4: SenseCAP Portal 云端数据查看与告警验证 {#verify_sensecap_portal type=web_dashboard required=true verify=true config=devices/sensecap_portal.yaml}

完成现场安装与标定后，登录 SenseCAP 智慧云平台，查看 LoRaWAN 网关接收到的巡检设备数据与振动告警事件。

### 接线

1. **网关就绪**：确保区域内的 SenseCAP M2 LoRaWAN 网关已正常联网并上线；

### 故障排查

| 问题 | 解决方法 |
|---|---|
| 设备在云平台上未激活/离线 | 确认现场 LoRaWAN 网关正常联网，检查 T1000-E 频段是否与网关一致（如 CN470、EU868、US915）；长按设备按键重启设备发起加入网络（Join）。 |
| 敲击振动后云端未收到告警 | 确认步骤 3 原生标定已成功回写基线；检查设备 LoRaWAN 信号覆盖（RSSI/SNR），等待下一个上报周期或触发急停告警包。 |
| 无法打开 SenseCAP 门户网站 | 确认网络可正常访问互联网；如果使用的是私有部署网关，请核对指向的服务器地址。 |

### 部署完成

你已成功完成 LoRaWAN 工业振动巡检方案的部署。T1000-E 终端将在工业现场长期自主运行，实时监测旋转机械振动状态，通过 LoRaWAN 远距离网络将异常隐患第一时间上报至云端。

## 套餐: Mesh 集中监控与地图看板 {#mesh_ha_bridge}

通过 USB 接收节点将 Meshtastic 离网自组网通讯桥接至 Home Assistant。现场贴合在工业机械上的 T1000-E 振动监测节点在完全无公网和 Wi-Fi 的环境下，通过 Mesh 空口广播 GPS 物理坐标与振动报警报文，并在 Home Assistant 原生地图上实现集中可视化监控。

> **准备工作**：用于振动监测的 T1000-E 需已烧录 VAD 固件并完成基线标定（可参考套餐 2 步骤 1 与 3 准备）；若直接使用出厂 Meshtastic 固件，设备将作为移动 GPS 追踪器并在长按按钮触发 SOS 时向 Home Assistant 报告振动/SOS 报警实体（`binary_sensor.vibration_<node_id>`），同时在地图上呈现 GPS 追踪位置。

| 设备 | 用途 |
|---|---|
| SenseCAP T1000-E（网关节点） | 通过 USB 数据线连接主机，作为接收节点接收空口报文并通过串口上报 |
| SenseCAP T1000-E（监测节点） | 刚性贴合于工业机械表面，检测振动异常并携带 GPS 物理坐标在 Mesh 中广播 |
| 运行主机 | 运行 Docker 环境，承载 Mesh-MQTT 串口桥接容器 |

## 步骤 1: 部署 Mesh-MQTT 串口桥接器 {#deploy_bridge type=docker_deploy required=true config=devices/meshtastic_bridge.yaml}

将 USB 接收节点收到的 Meshtastic Mesh 组网报文桥接至 MQTT Broker，并发布 Home Assistant MQTT Discovery 实体，实现振动报警与 GPS 地图追踪。

### 接线

1. 使用数据线将 Meshtastic 接收节点（如处于接收模式的 T1000-E 或 USB Dongle）插入主机的 USB 端口；
2. 确认串口设备路径（Linux 下通常为 `/dev/ttyACM0`）；
3. 在下方配置项中填入 MQTT Broker 连接参数并开始部署。

### 故障排查

| 问题 | 解决方法 |
|---|---|
| 找不到串口 `/dev/ttyACM0` | 检查 USB 数据线连接，在主机上执行 `ls /dev/ttyACM*` 确认设备路径。 |
| 容器健康检查未通过 | 确保 USB 接收节点已插入且 MQTT Broker 网络可达；运行 `docker logs vibration-mesh-bridge` 查看日志。 |
| 无法连接 MQTT Broker | 检查 Broker IP 地址、端口以及账号密码是否正确。 |

### 部署目标 {#deploy_bridge_local type=local device_name="Local Host" config=devices/meshtastic_bridge.yaml default=true}

部署到当前运行 Docker 的本地机器。

### 部署目标 {#deploy_bridge_remote type=remote device_name="Linux Host" config=devices/meshtastic_bridge.yaml}

通过 SSH 部署到运行 Docker 的 Linux 主机。

| MQTT 集成已存在 | 若 Home Assistant 中已存在生效的 MQTT 集成，直接跳过本步骤即可。 |

## 步骤 3: 准备与贴合安装 T1000-E 振动监测节点 {#mount_tracker type=manual required=true}

将 T1000-E 振动监测节点刚性贴合固定在被测工业旋转设备轴承座表面，实时捕捉异常振动并通过 Meshtastic 自组网广播。

> **准备工作**：用于振动监测的 T1000-E 需已烧录 VAD 固件并完成基线标定（可参考套餐 2 步骤 1 与 3 准备）；若直接使用出厂 Meshtastic 固件，设备将作为移动 GPS 追踪器并在长按按钮触发 SOS 时向 Home Assistant 报告振动/SOS 报警实体（`binary_sensor.vibration_<node_id>`），同时在地图上呈现 GPS 追踪位置。

### 接线

1. **开机启动**：长按 T1000-E 监测节点按键 3 秒，蜂鸣器响声后完成开机；
2. **频道确认**：确保监测节点的 LoRa 频段区域（Region）与主频道参数与接收网关节点保持一致；
3. **刚性贴合**：使用 **3M VHB 4910 亚克力胶带** 或高强磁吸底座将设备平整贴合在电机或水泵轴承座受力面，严禁使用发泡海绵胶；
4. **定位确认**：若需在地图上查看精确物理坐标，需确保监测节点在室外有良好的 GPS 信号视野。

### 故障排查

| 问题 | 解决方法 |
|---|---|
| 监测节点未发送广播 | 确认设备已开机，并检查其 LoRa 频段与频道是否与接收网关一致。 |
| 振动感应迟钝或失真 | 切勿使用吸震海绵材料，改用 3M VHB 4910 亚克力双面胶贴合于平整金属表面。 |

---

## 步骤 4: 查看 Home Assistant 集中监控地图 {#verify_map type=web_dashboard required=true verify=true config=devices/ha_dashboard.yaml}

打开 Home Assistant 地图看板，在地图上集中查看各监测节点的物理坐标，并实时接收机械振动异常告警。

### 接线

1. 在下方输入项中确认 Home Assistant 主机与端口（默认 `127.0.0.1:8123`）；
2. 点击 **打开仪表盘** 进入 Home Assistant 原生地图看板（`/map`）；
3. 确认地图上已呈现各监测节点对应的 `device_tracker.vibration_<node_id>` 实体与物理坐标；
4. 轻敲被测设备或模拟振动触发告警，确认 Home Assistant 中的 `binary_sensor.vibration_<node_id>` 状态变为 `ON`。

### 故障排查

| 问题 | 解决方法 |
|---|---|
| 地图上未出现设备追踪实体 | 确认 T1000-E 监测节点已完成 GPS 定位并成功广播位置包；运行 `docker logs vibration-mesh-bridge` 查看报文解析日志。 |
| 发生振动但传感器未显示告警 | 确认接收报文包含 `VIBRATION_ALERT` 或 `ALARM` 关键字；可在手机 Meshtastic App 或网关容器日志中核对消息文本。 |
| 无法打开地图页面 | 检查 Home Assistant 服务是否正常运行，并核对访问地址与端口（默认 `http://127.0.0.1:8123`）。 |

### 部署完成

基于 Meshtastic 与 Home Assistant 的集中监控地图方案已部署完毕。现场部署的 T1000-E 振动监测节点无需公网，即可通过离网 Mesh 将设备定位与异常告警汇总到中央看板统一呈现。
