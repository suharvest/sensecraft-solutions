## 这个方案能帮你做什么

工业现场经常同时存在多种设备通讯方式，同一栋楼或同一条产线的数据分散在不同控制器中。MissionPack 提供一个统一入口：添加控制器、确认点位、在总表查看实时值，再把选定数据通过受控 MQTT 服务提供给现场其他系统。

方案优先面向 reComputer R1000/R1100 系列和 reTerminal DM 系列，其中 reTerminal DM 可直接通过本机触控屏完成日常配置与操作。

预测流程作为可选插件保留。只使用协议接入、点位管理和数据服务时，不需要训练模型。

## 核心价值

| 好处 | 现场如何使用 |
|------|--------------|
| 接入常见工业协议 | 在同一管理界面配置 OPC UA、Modbus TCP、BACnet/IP 或 MQTT 数据源；Modbus RTU/RS-485 通过串口设备部署配置接入，并带明确的硬件验证门禁 |
| 先发现、再确认 | 浏览 OPC UA 节点、扫描 Modbus 站号、执行 BACnet Who-Is 或观察 MQTT 主题；候选点位经人工确认后才进入正式点位表 |
| 手动配置始终可兜底 | 支持发现的协议也允许工程师直接填写点位地址，避免特殊设备无法接入 |
| 一个总表管理全部点位 | 按数据源筛选点位，查看实时值和质量；下发控制命令前必须再次确认 |
| 给上层系统稳定的数据格式 | 内置 Broker 提供带版本的点位、在线状态、命令和回执主题，便于现场系统统一接入 |

## 适用场景

| 场景 | 怎么用 |
|------|--------|
| 楼栋能耗管理 | 把 BACnet/IP 空调机组和 Modbus 电表汇入一个点位表，再将选定数据送到能耗看板 |
| 暖通改造 | 保留现有 OPC UA 控制器，同时加入新的 MQTT 传感器，不重写原有控制程序 |
| 小型工业协议网关 | 安装在配电柜旁的 reComputer R1000/R1100 或 reTerminal DM 上，对客户上位系统统一提供 MQTT 数据 |
| 受控节能优化 | 使用可选预测插件导入 CSV、选择输入输出点位，并查看每次控制命令的回执 |

## 使用须知

### 核心硬件设备

| 设备 | 说明 | 必需 |
|------|------|------|
| reComputer R1000 系列 | 运行协议连接、点位注册表、MQTT 数据服务和管理界面 | 三选一 |
| reComputer R1100 系列 | 运行协议连接、点位注册表、MQTT 数据服务和管理界面 | 三选一 |
| reTerminal DM 系列 | 运行工业协议网关，并通过本机触控屏完成配置与日常操作 | 三选一 |
| USB 转 RS-485 适配器 | 连接 Modbus RTU 总线 | 仅 Modbus RTU 需要 |

### 网络与协议边界

- 网关必须能够访问各以太网协议所在网络。BACnet 广播发现可能需要选择正确网卡，并保证设备位于可达网段。
- OPC UA 浏览、BACnet Who-Is、Modbus TCP 站号扫描和 MQTT 主题观察只生成候选项；用户确认后才会进入正式点位表。
- 已包含 Modbus RTU 配置和通讯能力，但标准 Docker 配置不会挂载主机串口。需要使用串口设备安装方式；在指定 USB 转 RS-485 适配器与目标控制器通过真实硬件联调前，生产写控制必须保持关闭。
- 远程 Linux 部署使用主机网络，以便 BACnet/IP 广播发现进入物理网段；Docker Desktop 的本机桥接部署可能需要手动填写 BACnet 地址。
- 部署时会先运行一个无网络的一次性卷权限迁移任务，再启动非 root 网关服务。它会保留旧 root 镜像生成的数据，同时让长期运行进程保持无特权身份。
- 北向数据服务使用原生 **MissionPack v1 MQTT 主题契约**。它借鉴工业设备生命周期消息，但当前版本**不宣称兼容 Sparkplug B**。
- 明文 MQTT 只允许遥测数据。需要远程控制时，必须启用 TLS 并配置具有控制权限的身份。
